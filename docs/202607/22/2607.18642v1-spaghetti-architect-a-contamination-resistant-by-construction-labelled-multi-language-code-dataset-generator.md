## 摘要
挖掘而来的代码语料库虽然丰富，但缺乏控制：代码片段的语义、表面的“杂乱性”以及难度完全取决于自然生成的内容；没有已知的最优参考用于评分；而且任何公开样本可能已经存在于模型的训练集中。我们提出了Spaghetti Architect，这是一个能够生成代码数据集工具，提供了这些语料库所缺乏的控制能力。一个反优化转译器将干净、语言无关的JSON中间表示映射为五种语言（Python、JavaScript、Go、Java、C++）中故意冗余、完全扁平化的程序；每个程序都会被编译、运行，并对照参考预言进行验证，因此每个实例在构造上就是正确的。干净的中间表示是已知的最优参考，杂乱程度通过严格嵌套的反模式配置文件进行调节，每个实例沿着两个正交的难度轴进行标注：内在难度（问题规模）和偶然难度（固定语义下的呈现方式），并且通过从私有保留种子中生成新的变体来抵抗污染。我们提供了构念效度证据，表明质量顺序影响了已有的复杂性和可读性指标，并报告了在四个模型开放阶梯上的基线结果：精确匹配随规模增大而上升，内在旋钮使最强模型的算术聚合准确率降至零。此外，开发集分数与全新生成的保留对应分数在理解上差异|Δ|≤0.012，在重构上≤0.011；在相同程序上，重构等价性（0.73→0.99）是规模不变的，而输出预测则崩溃；消融生成器的自标注显示，它们使最弱模型的增幅比最强模型高一个数量级（-0.173 vs -0.017）：标注阶梯解决了三个相邻对中的一个，而未标注阶梯则解决了全部三个。开源（MIT），无依赖，持久DOI存档。

## Abstract
Mined code corpora are abundant but uncontrolled: a snippet's semantics, surface "messiness," and difficulty are whatever the wild contained; there is no known-optimal reference to grade against; and any public sample may already sit in a model's training set. We present Spaghetti Architect, a tool that mints code datasets with the control such corpora lack. An anti-optimization transpiler maps a clean, language-agnostic JSON intermediate representation to deliberately redundant, fully-flattened programs in five languages (Python, JavaScript, Go, Java, C++); every program is compiled, run, and checked against a reference oracle, so each instance is correct by construction. The clean IR is a known-optimal reference, messiness is dialed by strictly-nested anti-pattern profiles, each instance is labelled along two orthogonal difficulty axes, intrinsic (problem size) and incidental (presentation at fixed semantics), and contamination is resisted by minting fresh variants from a private held-out seed. We give construct-validity evidence that the quality order moves established complexity and readability metrics, and report baselines on a four-model open ladder: exact match rises with scale, and the intrinsic knob collapses arithmetic-aggregation accuracy of even the strongest model to zero. Further, development-set scores equal freshly re-minted held-out counterparts within $|Δ|\le 0.012$ (comprehension) and $\le 0.011$ (refactoring); on identical programs, refactoring equivalence ($0.73 \rightarrow 0.99$) is scale-invariant while output prediction collapses; and ablating the generator's self-annotations shows they inflate the weakest model an order of magnitude more than the strongest ($-0.173$ vs $-0.017$): the annotated ladder resolves one of three adjacent pairs where the unannotated resolves all three. Open source (MIT), dependency-free, archived under a persistent DOI.

# 论文深度总结：Spaghetti Architect

## 1. 核心问题与研究动机

- **研究背景**：现有代码数据集主要来自挖掘（scraping）开源仓库，这种方式存在三个根本缺陷：
  - **缺乏控制**：代码的语义、表面“杂乱性”和难度完全由自然内容决定，无法独立调节。
  - **缺少最优参考**：没有已知的最优程序作为评分基准，难以判断模型是否真正理解代码。
  - **训练集污染**：任何公开的代码样本都可能已出现在模型训练集中，导致高分数可能来自记忆而非能力。
- **核心问题**：如何生成一种可控制、带有明确标签、且能抵抗污染的多语言代码数据集，用于公平、可重复的模型评估。
- **整体意义**：提供一种可生成、带正交难度标签、正确性可验证的代码数据集生成工具，从根本上解决挖掘语料库的不可控性和污染问题，支撑数据中心的机器学习研究（如模型评估、稳健性分析、重构能力探测等）。

## 2. 方法论

### 核心思想：反优化转译（Anti-Optimization Transpilation）

- 将一种语言无关的JSON中间表示（IR）映射为五种语言（Python、JavaScript、Go、Java、C++）的故意冗余且完全扁平化的程序。
- 每个生成的程序都经过编译、运行，并与预言机（oracle）比较输出，确保构造即正确（correct by construction）。
- **关键技术细节**：
  - **IR操作**：四种基本操作 – `MEMBERSHIP_CHECK`（成员检查）、`KEY_VALUE_LOOKUP`（键值查找）、`AGGREGATE`（聚合：sum/min/max）、`CONDITIONAL_SELECT`（条件选择）。每个操作读取验证过的输入并写入新变量。
  - **反模式数据库**：11种SPAGH_*转换，分为7类（结构、冗长、噪声、防御、控制、性能、布局），来源于Collberg-Thomborson混淆分类和经典代码坏味（Fowler, 2018）。
  - **严格嵌套剖面**：六个嵌套级别（`clean ⊂ minimal ⊂ light ⊂ standard ⊂ heavy ⊂ max`），每个级别添加转换而不移除任何已有的，形成严格的质量顺序（但`light`和`standard`实际输出相同，因为新转换在所有语言中均不可达）。
  - **双正交难度轴**：
    - **内在难度（Intrinsic）**：问题规模，通过操作链长度、集合宽度（W）、查找列表长度（L）、条件分支数量（T）等控制。
    - **偶然难度（Incidental）**：固定语义下的呈现质量，通过反模式剖面控制。
  - **污染防护协议**：
    - 公开开发集（dev split，100个实例）和私有保留测试集（test split，从秘密种子生成，永不提交）。
    - 三级对抗污染能力：A级（重调字面量）、B级（使用公开集从未出现的结构形状）、C级（超出公开集规模和深度范围的组合）。
    - 嵌入金丝雀GUID，便于检测训练集泄露。
  - **自标注**：每个输出程序自动附带头部注释、操作意图注释和部分反模式的内联标记（SPAGH_*），帮助模型理解但可能导致分数膨胀。

### 算法流程（文字描述）

1. 输入：干净的JSON IR（由四种操作组成）。
2. 解析器：验证IR的合法性，转换为类型化模型。
3. 规划器：根据选择的反模式剖面（messiness knob）从反模式数据库中选取合适的转换。
4. 五个生成器（每种语言一个）：通过代码发射器生成源代码，确保正确的缩进/括号结构始终安全（try/catch + 守卫 + 预设回退）。
5. 验证器：编译并运行每个目标程序，与参考预言比较输出；若缺少工具链则跳过（不会静默通过）。
6. 输出：两种轴标签的数据集（内在规模、偶然混乱度），分为公共开发集和私有测试集。

## 6. 主要结论与发现

1. **生成数据质量可控**：静态复杂性指标（圈复杂度、认知复杂度、可维护性指数）与偶然混乱度旋钮单调相关（Spearman ρ: +0.75~+0.80），且跨五种语言一致（lizard CC ρ≈+0.35，token count ρ=+0.88）。可读性信号较弱但仍正相关（Buse-Weimer ρ=+0.39）。
2. **污染抵抗验证**：公共开发集与私有Tier-A测试集在理解精确匹配上偏差|Δ|≤0.012，在重构语义等价率上|Δ|≤0.011（最强模型Δ=-0.0001），证明重铸后难度保持。
3. **能力阶梯有效**：comprehension EM从Llama-3.1-8B（0.55）上升到DeepSeek-V4-Flash（0.84），refactoring语义等价率从0.73上升到0.99，数据集能够区分模型能力。agg_stats家族最为困难，最强模型仅达到0.33。
4. **内在规模旋钮可导致模型失败**：在agg_stats上，随着集合宽度W从8增加到64，所有模型（包括最强）的精确匹配降至零（表7），而config_resolver无此现象。
5. **双任务分离能力**：在相同agg_stats程序上，重构语义等价率对W不敏感（最强两模型≥0.95），而输出预测随W崩溃，从而分离出宽度敏感的计算能力与宽度不变的等价重构能力。
6. **注释消融揭示膨胀效应**：生成器的自标注（注释）在重构任务上使所有模型分数升高，但对最弱模型的影响（-0.173）比最强模型（-0.017）大约一个数量级；未标注条件下能力阶梯可分辨全部三个相邻对，而标注条件下只能分辨一个。这种差异膨胀压缩了能力阶梯。
7. **头房间隙**：agg_stats在私有测试集上（Tier A）仍远未饱和，最强模型仅0.33，为未来模型留出改进空间。

## 7. 优点

- **方法论创新**：反优化转译和构造即正确的设计，首次提供严格嵌套的、可验证语义等价的多语言代码质量顺序。双正交难度轴独立调控内在和偶然因素，这是任何挖掘语料库无法提供的。
- **污染防护机制**：通过私有种子、三级抗污染等级、金丝雀GUID，以及公共/私有不对称，使得每次评估都可以生成全新实例，从根本上减少记忆效应。且通过实验证实了开发集与保留集的分数一致性。
- **完整开源的资源**：MIT协议，无Python标准库外依赖，包含验证器、测试套件、文档和可重复生成合约。持久DOI存档，符合FAIR原则。
- **全面的验证**：不仅使用静态度量（圈复杂度、认知复杂度、可维护性指数），还跨语言用lizard验证；提供了非学习基线（clean-ceiling、自动格式化器、规则简化器）来界定任务难度范围；报告了不确定性（bootstrap CI、leave-one-family-out稳健性）。
- **丰富的能力分离结果**：通过内在规模扫描，在相同输入上分离出计算能力与等价重构能力，为理解模型的结构行为提供诊断工具。
- **注释消融发现**：揭示了基准自带注释会不公平地夸大弱模型表现，损害排名分辨率，为未来代码评估基准设计提供了重要警示。

## 8. 不足与局限

- **实验覆盖不完整**：
  - 仅测试了四个开放模型，未包括GPT-4、Claude等更强模型，也未包括更弱的模型（小于8B）。
  - 构造效度完全依赖静态度量，没有人类程序员参与评级的实验（作者将人类排名研究列为未来工作）。因此“质量顺序”未被直接验证为人类感知。
  - 注释消融仅在k=1下进行，尽管有论证但与k=8的差异很小，但并非直接复制。
  - 内在规模扫描仅针对agg_stats家族，其他家族未展示类似曲线。
  - 只使用了一个私有种子进行重铸，未评估种子间方差。
  - 实验的API调用有时间差（annotated与unannotated臂相隔约两周），未控制服务端漂移。
- **生成器范围有限**：
  - 仅支持四种操作、整数操作数（AGGREGATE和CONDITIONAL_SELECT限制整数是为了跨语言输出一致性），不支持任意控制流、浮点数、对象方法、项目级代码。
  - 生成的是单文件程序，不代表真实代码库的复杂性。
  - 一个旋钮级别（light和standard）实际上相同（由于两个转换不可达），降低了旋钮的区分度。
- **污染防护的边界**：
  - 私有测试集的字面值可通过已发布的模型补全恢复（因为重构补全包含大部分输入字面量），因此当前版本的私有集在发布后实际上不再保密。
  - Tier B/C的形状在代码中是公开的，仅种子保密，因此保护的是下次重铸的新字面量，而非结构。
