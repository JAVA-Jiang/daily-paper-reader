## 摘要
科学机器学习论文通常包含计算声明，例如相对均方误差小于5%或95%预测可信区间覆盖测试数据。仅凭论文材料，可以提示编码智能体复现这些声明，但提示本身并不能可靠地保留进展或检查生成的证据是否支持论文的声明。我们引入了Paper-replication工作流，该工作流将每个选定的论文声明作为带有记录证据的目标，并将其实现为编码智能体的技能。该工作流使智能体记录这些目标，重构论文的方法，运行计算实验，将生成的输出与来源和与论文声明的比较联系起来，记录匹配证据出现在复现报告中的位置，并在完成前通过验证检查。我们在四篇科学机器学习论文的十二次独立运行中评估了Paper-replication。所有十二个工作区均通过了完成门控，所有158个记录的目标均与报告覆盖范围匹配。即使在此完成的工作区状态下，重复运行在如何将论文划分为目标、对源论文的数值保真度、复现耗时、最终证据被接受前被替换的中间执行次数以及用于接受证据的规则上存在差异。Paper-replication使完成依赖于工作区证据和验证检查，而不是智能体的最终消息。

## Abstract
Scientific machine learning papers typically make computational claims, e.g., that the relative mean square error is less than 5% or that the 95% predictive credible interval covers the test data. A coding agent can be prompted to replicate those claims from paper materials alone, but the prompt does not by itself reliably preserve progress or check whether generated evidence supports the paper's claims. We introduce Paper-replication, a workflow that makes each selected paper claim a target with recorded evidence, and implement it as a coding-agent skill. The workflow makes the agent record those targets, reconstruct the paper's method, run computational experiments, link generated outputs to provenance and comparisons with the paper's claims, record where matched evidence appears in the replication report, and pass validation checks before completion. We evaluate Paper-replication on twelve independent runs across four scientific machine learning papers. All twelve workspaces pass the completion gate, and all 158 recorded targets are matched with report coverage. Even in this completed workspace state, repeated runs differ in how papers are divided into targets, in numerical fidelity to the source papers, in elapsed replication time, in the number of intermediate executions replaced before final evidence is accepted, and in the rules used to accept evidence. Paper-replication makes completion depend on workspace evidence and validation checks rather than on the agent's final message.

## 2. 论文提出的方法论

### 2.1 核心思想
- 将每篇论文的可复现计算声明定义为**目标**（target），每个目标对应一个**证据束**（evidence bundle）：包含生成输出、执行记录、来源链接、与论文声明比较的证据、报告覆盖位置。
- 通过**持久化工作空间**（persistent workspace）存储状态，通过**外部验证检查**（validation checks）决定证据是否可被接受，而非仅靠智能体对话。
- 设计为**编码智能体技能**（coding-agent skill），复用现有Agent（Codex、Claude Code）的文件操作和命令执行能力。

### 2.2 关键技术细节
- **工作空间结构**：包含清单（manifest）、再现矩阵（reproduction matrix）、任务账本（task ledger）、规格文件（specification files）、运行记录、来源记录、比较证据、报告覆盖等文件。
- **目标定义**：对于每个目标 \(t_j\)，要求记录：
  - 生成输出 \(\hat{y}_j = F_j(D_j;\theta_j,\omega_j)\)
  - 执行记录 \(R_j\)
  - 来源记录 \(P_j\)（代码、配置、种子、论文引用）
  - 比较证据 \(C_j\)（基于目标接受的规则）

- **验证检查**：包括规格检查（文件存在）、进度检查（任务账本与矩阵一致、来源哈希、比较证据形式）、报告覆盖检查、完成门控（所有目标MATCHED、无活动目标、报告PDF存在）。

### 2.3 算法/流程描述（文字）
1. **初始化**：智能体读取论文源文件（LaTeX、图、表、数据引用），记录清单和哈希，编译PDF并转为图片。
2. **记录目标列表**：在再现矩阵中列出每个需要复现的声明及其属性（论文位置、重建方法、输出格式、评判规则、状态）。
3. **重建方法论**：在规格文件中记录方程、算法、假设、未解细节和测试假设的实验。
4. **实验执行**：每次实质性执行通过运行记录器记录命令、时间、成功标志、输出文件哈希。
5. **比较与记录证据**：将生成输出与论文声明比较，按接受的规则判断，记录来源和比较证据。
6. **报告覆盖**：将匹配的结果写入复现报告，记录位置。
7. **验证与完成**：运行外部检查，若所有目标MATCHED且无活动目标且报告存在，则工作空间标记为完成。

- **实用性**：实现为编码智能体技能，可复用现有Agent的文件和命令操作能力，无需定制Agent架构。
- **可记录变异性**：工作空间保留了目标分解、执行历史、修正过程、接受规则等细节，使得分析复现变异性成为可能，而不仅仅是二值结果。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅覆盖4篇论文，12次运行，一个Agent接口（Codex+GPT-5.4），一个推理设置。结论的外部推广性受限。
  - 没有进行消融实验来估计Paper-replication相对于普通提示的独立效果（如“无技能基线”）。
  - 标量锚点仅13个，PIFT没有标量锚点，无法用统一尺度评估其数值保真度。
- **偏差风险**：
  - 重复运行使用相同论文材料、提示模板、计算环境，但目标分解、接受规则类型等仍出现变异，说明Agent本身的随机性和理解差异。
  - 作者承认，即使哈希检查排除了直接抄袭，Agent仍可能通过变换重用论文资产，虽然未观察到。
- **方法局限**：
  - 完成门控仅要求记录的目标全部匹配，而没有验证目标是否覆盖了论文所有声明。若Agent遗漏了重要声明而不记录为目标，仍可完成。
  - 标量阈值（如PINN-II的10%系数误差）是分析者设定的论文报告精度，而非Agent自主判断的阈值，因此“MATCHED”状态和“落在固定阈值内”可能不一致（文中确实有2例超出固定阈值但仍被Agent接受为MATCHED）。
  - 分布/结构目标的“通过”标准宽松，仅依赖智能体记录的描述性比较，缺乏定量检验。
- **应用限制**：
  - 要求计算环境至少能运行相关实验（如神经网络训练），对缺乏足够算力的场景不适用。
  - 当论文省略关键细节（如种子、预处理步骤）时，Agent必须猜测，尽管记录假设，但不同猜测可能导致分歧。
- **重复性验证**：由于使用商业模型（GPT-5.4）且可能随时间变化，严格复现本文结果可能困难。
