## 摘要
我们提出 FindMyText，一个开源的 Python 包，旨在高效评估给定文本是否部分或全部出现在文本语料库中。该工具建立在先前的文档指纹识别技术之上，但通过一种新颖的机制扩展了它们，以显式捕获匹配指纹的序列。通过识别这样的链，该工具可以更可靠地检测给定文本的近乎逐字副本，而不仅仅是文本相似性。这使得 FindMyText 特别适用于验证语料库中受版权保护材料的存在性。利用分布式的、基于磁盘的索引框架，该系统可以扩展到大规模的网络抓取数据集。使用一个新的基准来评估文本包含方法，我们表明 FindMyText 在三个数据集（ArXiv 论文、维基百科和通用网络内容）上优于其他方法。

## Abstract
We present FindMyText, an open-source Python package designed to efficiently assess whether a given text appears, in part or in full, within a text corpus. The tool builds on prior techniques for document fingerprinting, but extends them with a novel mechanism to explicitly capture sequences of matching fingerprints. By identifying such chains, the tool can more reliably detect near-verbatim copies of a given text rather than mere textual similarities. This makes FindMyText particularly suited for verifying the presence of copyrighted material in a corpus. Leveraging a distributed, disk-based indexing framework, the system scales to large web-crawled datasets. Using a new benchmark for evaluating text containment methods, we show that FindMyText outperforms alternative approaches across three datasets (ArXiv papers, Wikipedia, and generic web content).

### 1. 核心问题与整体含义（研究动机和背景）
- **问题**：在大规模网络抓取语料库（如LLM预训练数据）中，判断一个给定文本是否（部分或全部）包含在语料库内，即**文本包含检测（text containment）**。不同于语义相似性或近重复检测，它要求识别共享文本片段，尤其关注**近乎逐字复制**的情况，这对于版权侵权检测至关重要。
- **背景**：LLM训练数据常来源于爬虫，但提供商不愿披露具体内容，导致无法有效评估数据来源。现有方法（如基于语义嵌入、MinHash指纹、简单共享指纹计数）难以区分“真正包含”与“主题相似但文本不同”的情况，且对预处理（格式化、标准化、分段等）不鲁棒。法规（如EU AI Act）要求提高透明度，但核心技术挑战依然存在。

### 2. 方法论：核心思想、关键技术细节、算法流程
- **核心思想**：基于**文档指纹（winnowing）** 构建倒排索引，但不再仅统计共享指纹数量，而是通过**捕获连续匹配指纹的链（fingerprint chains）** 来定位共享文本片段。这种方法能有效区分“偶然局部相似”与“真正的文本包含”。
- **关键技术细节**：
  - **预处理步骤**：
    1. 分词（words），提取k-gram（k=4，忽略标点），并哈希化。
    2. 对哈希序列应用winnowing（窗口w=6），在每个窗口内选择最小哈希作为指纹，去除重复。保证长度≥k+w-1的子串必然有至少一个共同指纹。
    3. 为每个文档构建指纹列表，并存入倒排索引，映射指纹→（文档ID，位置对）。
  - **文本包含检测**：
    - 方法1：**共享指纹数**（`snb_shared`），直接计数查询文本q与候选文档di共享的唯一指纹数。但忽略位置顺序。
    - 方法2：**指纹链检测**（`schain`）：基于共享指纹的位置偏移（`δ(h) = p_di(h) - p_q(h)`），将匹配点视为二维空间点（`p_q(h), δ(h)`）。若两个匹配点的`p_q`之差≤`τ_pos=30`且`δ`之差≤`τ_off=10`，则认为它们相连，通过聚类算法提取连通簇，丢弃小于`κ=5`个指纹的簇，最终分数为最大簇的大小。
  - **索引存储**：分布式基于磁盘的索引框架（内存映射数组），支持超大规模语料。
- **算法流程**（图1总结）：
  1. 对语料库C，提取所有文档的winnowing指纹，构建倒排索引。
  2. 对查询q，提取其指纹，在索引中查找共享指纹。
  3. 对每个候选文档，计算共享指纹及其位置。
  4. 应用链式聚类方法，输出最大链长度作为分数。

### 6. 主要结论与发现
- 基于**链式指纹检测**的方法在三个数据集上均实现**AUC-ROC ~0.99 以上**，显著优于其他方法。
- **BM25和密集检索**无法区分语义相似但无包含的负实例（AUC-ROC接近0.5甚至更低）。
- **简单共享指纹计数**在长文档（如ArXiv）上性能差（AUC-ROC 0.335），因为长文档偶然共享指纹多，无法过滤噪声。
- 当共享文本片段**变短**（神谕阈值500）时，链式方法仍保持高性能（AUC-ROC ~0.98-1.0），而共享指纹计数大幅下降（ArXiv上仅0.122）。
- 链式方法对编辑、噪声、添加无关内容具有鲁棒性，尤其适合检测版权材料。

### 7. 优点
- **方法创新**：首次将链式聚类用于文本包含检测，有效利用位置信息区分真正包含与偶然相似。
- **可扩展性**：分布式、磁盘索引，支持超大规模语料（HPLT 5070万文档，查询毫秒级）。
- **鲁棒性**：参数（`τ_pos`, `τ_off`, `κ`）经校准，对小编辑（连字符、大小写、字符替换等）不敏感。
- **开源实用**：提供Python包和web界面（https://findmytext.nr.no），支持可视化匹配片段。
- **基准设计合理**：Smith-Waterman神谕结合编辑操作模拟真实预处理，负实例构造严格（相似但无包含）。

### 8. 不足与局限
- **实验覆盖有限**：仅测试了英语文本，多语言场景未验证；语料仅为Web-crawl、维基、ArXiv，缺乏领域如法律文档、学术论文全文（ArXiv只有CC许可论文）。

- **与其他文本对齐工具的对比缺失**：未与BLAST或其他生物信息学/字符串对齐工具进行公平比较，仅将其作为神谕。
