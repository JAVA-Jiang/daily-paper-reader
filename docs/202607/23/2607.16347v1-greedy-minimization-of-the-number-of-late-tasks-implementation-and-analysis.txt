Abstract 

We study the classical single-machine deadline problem 1 || P Uj , in which each task has a deadline and an execution requirement and the goal is to select as many on-time tasks as possible. The standard Moore-Hodgson algorithm processes tasks by deadline and may later delete a previously accepted task. We study the insertion-only shortest-job-first rule of Lin and Wang: process the tasks in nondecreasing execution requirement, and accept a task exactly when doing so preserves feasibility. We give a direct O(n log n)-time implementation using a balanced augmented BST keyed by deadline. Unlike the previous O(n log n) implementation of this SJF rule, our implementation needs neither a preëmptive schedule nor an amortized analysis of interval changes. Our analysis gives an explicit threshold form of the rule’s lexicographic ( lex-first ) optimality: for every threshold e, its outputs maximize the number of selected tasks whose execution re-quirement is at most e. The analysis also reveals additional combinatorial structure. After the shorter tasks have been greedily fixed, the feasible choices within a single execution-requirement tier form a nested matroid. These tier matroids assemble, as a direct sum, into an overall lami-nar matroid whose bases are exactly the greedy outputs. Finally, a flow network encoding the deadline-prefix constraints gives a polymatroid rank function for the underlying scheduling feasi-bility structure. This flow view also recovers the nested matroids that govern the equal-execution tiers. 

# 1 Introduction 

Let S be a set of n nonpreëmptive tasks, all available at time zero on one machine. Each task has a positive execution requirement and a positive deadline. We seek a maximum-cardinality subset whose tasks can all meet their deadlines; equivalently, we seek an execution order that minimizes the number of late tasks. This classical problem is denoted by 1 || P Uj .By Jackson’s rule [6], a task set is feasible if and only if its tasks meet their deadlines in earliest-deadline-first (EDF) order. Equivalently, for every deadline d, the total execution requirement of tasks with deadline at most d must be at most d. These deadline-prefix inequalities are the basis of both our analysis and our implementation [5, 10]. Our starting point is the insertion-only SJF-greedy rule of Lin and Wang [7]. The rule processes tasks in nondecreasing execution requirement and accepts a task exactly when adding it preserves feasibility. Thus, unlike the Moore–Hodgson rule [8], it never removes a previously accepted task. The rule is simple to state, but a direct implementation may spend O(n) time checking deadline prefixes for each of n tasks. The resulting O(n2) bound leaves open the question of whether the insertion-only rule itself admits a simple efficient implementation. 1arXiv:2607.16347v1 [cs.DS] 16 Jul 2026 Zhao and Yuan [12] gave the first fully specified O(n log n) implementation. Their algorithm uses SPT order with EDF tie-breaking and maintains a backward preëmptive schedule represented by a DD-interval family. Candidate tests search backward through idle gaps, and the total number of interval operations is bounded amortized. Their framework also solves the number–length tradeoff: for every attainable cardinality k, it produces a feasible k-task set of minimum total execution requirement. We give a different implementation of the same SJF-greedy rule. Our data structure stores only two aggregates per deadline-tree node: total execution work and minimum deadline-prefix slack. A candidate is handled by one point insertion, one constant-time root test, and, if the test fails, one rollback deletion. Consequently every candidate takes worst-case O(log n) time, and the complete algorithm runs in O(n log n) time. The implementation does not represent a schedule, maintain a DD-interval family, or require an amortized interval-change argument. Its advantage is therefore simplicity of maintained state and analysis, rather than a better asymptotic total bound. It also permits arbitrary tie-breaking within equal-execution-requirement tiers. In addition to the implementation, we develop the structure of all possible SJF-greedy outputs: 1. Every greedy prefix minimizes total execution requirement among feasible sets of the same cardinality. This yields a threshold characterization of lex-first optimality and extends the fixed-order cardinality result of Lin–Wang and Zhao–Yuan. 2. Tie-breaking is confined to equal-execution-requirement tiers. After shorter tiers are fixed, the possible choices in the next tier form a nested matroid; their direct sum is a laminar matroid whose bases are exactly the possible greedy outputs. 3. A flow formulation of the deadline-prefix constraints yields a polymatroid rank function and provides a second, global description of the scheduling feasibility structure. The remainder of the paper first defines the SJF-greedy rule and proves its prefix and tier properties. We then present the augmented-tree implementation and compare it with Zhao–Yuan’s DD-interval structure. The later sections develop the matroid and flow viewpoints; an appendix recalls Moore’s original shortest-processing-time algorithm for context.

The algorithm studied in this paper is an insertion-only rule. It first orders tasks by nondecreasing execution requirement, with arbitrary tie-breaking within each execution-requirement tier. 3.2 Structural consequences 

The greedy rule has two logically separate aspects. First, its feasibility test is local: when a task is considered, only the current accepted set and the candidate matter. Second, the length-ordered scan has strong global consequences. The proofs later in the paper show that every greedy prefix is execution-minimal among feasible sets of the same cardinality, that tie-breaking matters only within equal-length tiers, and that the possible choices in each tier form a nested matroid. Their direct sum describes all possible greedy outputs. These structural facts explain what the rule selects, but none is needed to implement the feasibility test efficiently. This separation is important for the algorithmic contribution. The implementation below does not maintain a schedule, reconstruct an EDF order, or use any of the tier or matroid structure. It maintains only the deadline-prefix inequalities needed to decide whether one tentative insertion is feasible.

4.2 Overview of the Zhao–Yuan implementation 

The purpose of this subsection is to highlight the main ideas underlying the Zhao–Yuan data struc-ture; it is not a replacement for their full description and proofs [12]. Their first key observation is that a task set has a feasible nonpreëmptive schedule if and only if it has a feasible preëmptive schedule. Their data structure maintains a preëmptive representation of the current feasible set. The accepted tasks are scheduled backward from their deadlines: for each task, unused time is allocated as late as possible until the task’s execution requirement has been met. The occupied portions of the resulting schedule are stored as an ordered family of contiguous intervals. To test a candidate α with deadline d and execution requirement e, the algorithm locates the rightmost occupied interval whose start is at most d and scans the preceding idle gaps. It accepts 

α when the available idle time reaches e before time zero; the intervals encountered by this scan are then deleted and replaced by one interval. If the available idle time is insufficient, the candidate is rejected. In that case, Zhao and Yuan modify the prefix of the schedule by packing the tasks in that prefix as early as possible. This lets the same interval family absorb a failed search rather than paying for the same intervals repeatedly. For context, Zhao and Yuan formalize this representation using a DD-schedule . In their Defini-tion 2.1, a DD-schedule consists of a feasible schedule whose occupied intervals satisfy two conditions: each noninitial interval ends exactly at the maximum deadline of the tasks it contains, and no un-selected task with deadline no larger than the schedule’s current frontier can be inserted feasibly. The corresponding ordered collection is a DD-interval family . Their Lemma 2.4 establishes that the maintained interval family corresponds at every iteration to the same accepted set as the Lin–Wang greedy algorithm; their Theorem 2.1 then gives the O(n log n) running time. At a high level, the amortization is as follows. A successful insertion merges the intervals examined by the backward scan. A failed insertion merges the relevant prefix after it is repacked from the origin. Across the entire run, the number of interval finding, deletion, and insertion operations is O(n), so the ordered-list operations give an amortized O(n log n) bound. This is a different guarantee from the worst-case per-candidate bound of the augmented deadline tree above.

Both implementations begin with the same SJF insertion rule and have O(n log n) total running time after sorting. Our advantage is specifically simplicity of maintained state and a worst-case update 6guarantee, not universal superiority: the Zhao–Yuan interval framework supports their separate number–length tradeoff analysis. # 7 A Network Flow Perspective 

The exchange proof has a global counterpart. The deadline-prefix inequalities are cut constraints in a simple flow network, and the resulting maximum-flow value is a submodular function of the selected task set. This viewpoint is useful for two reasons. First, it gives a single global certificate for feasibility and quantifies the amount of work that can pass through the deadline prefixes even when a set is infeasible. Second, after the shorter tiers are fixed, contracting the corresponding feasible flow recovers the nested tier matroids. Thus the flow construction explains why the tier constraints have their nested form, rather than providing a second implementation of the algorithm. The augmented BST of Section 4 remains the implementation of the O(n log n) algorithm; the flow network is used only for the structural results in this section. SJF-greedy computes a lex-first maximum-cardinality feasible task set. Although the family of all feasible task sets need not be a matroid, the choices within each equal-execution tier form a nested matroid once the shorter tiers have been fixed. The direct sum of these tier matroids has exactly the greedy outputs as its bases, while the flow formulation places the same deadline-prefix constraints in a polymatroid. Algorithmically, deadline-prefix slack yields a direct O(n log n) implementation using two sum-maries in a balanced deadline tree. The selection rule never revokes an earlier acceptance: each candidate is tentatively inserted, and only an infeasible candidate is immediately rolled back. This implementation avoids the backward preëmptive interval family and amortized interval-change anal-ysis used in the previous O(n log n) implementation of the same rule. 

# A Moore’s Algorithm 

For comparison, we reproduce Moore’s description of his SJF algorithm [8]. The algorithm consists of a decision rule for dividing the set of jobs into two subsets. This division produces an optimal schedule if the jobs in the first set are sequenced according to their due-dates, and are followed by the jobs in the second set in any order. 

Step 1: Order the set of jobs according to the shortest processing time rule and call the resulting ordering (Ji1 · · · Jin ), where ti1 ≤ · · · ≤ tin , the current sequence. 

Step 2: Using the current sequence, find the first late job, Jiq , and go to Step 3. If no such job is found, the algorithm terminates with an optimal schedule obtained by ordering the jobs in the current sequence according to their due-dates followed by the set of jobs that have been rejected in any order. 

Step 3: Reorder the jobs, Ji1 · · · Jiq , according to the due-date rule producing a sequence of the form: 

Jℓ1 · · · Jℓq , J iq+1 · · · Jin where Dℓ1 ≤ · · · ≤ Dℓq .

There are two cases to consider: 1) If all the jobs in the subsequence Jℓ1 · · · Jℓq are early, define the total sequence as the current sequence and go to Step 2. 2) Otherwise reject the job Jiq and remove it from the sequence Jℓ1 · · · Jℓq Jiq+1 · · · Jin .Now go to Step 2 with the resulting sequence as the current sequence.
