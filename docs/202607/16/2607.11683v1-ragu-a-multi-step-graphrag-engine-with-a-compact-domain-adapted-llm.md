## 摘要
图检索增强生成（GraphRAG）通过结构化知识增强了大型语言模型，但现有系统在单次提取过程中构造知识图谱，产生噪声实体和脆弱的检索。RAGU是一个开源模块化GraphRAG引擎，通过将提取与合并分离来解决这一问题：实体和关系经过两阶段类型化提取、基于DBSCAN的去重、LLM摘要和Leiden社区检测。一个关键洞察促使了紧凑型提取器的设计：流水线中的LLM所需的技能——理解、提取、基于上下文推理——是与模型规模弱相关的语言技能，与事实性世界知识不同。因此，我们训练了Meno-Lite-0.1，一个针对语言技能优化的7B模型，它在知识图谱构建上优于Qwen2.5-32B（相对调和平均提高12.5%），在英文GraphRAG任务上与之持平。在GraphRAG-Bench（医学）上，RAGU在每个事实层级检索到最完整的上下文（证据召回率高达0.84，对比≤0.76），并在综合任务上超越HippoRAG2；在多跳事实问答上，HippoRAG2的明显优势在很大程度上被证明是答案格式的假象。RAGU可通过pip install graph_ragu安装，在单GPU上运行，并以MIT许可证发布。源代码可从https://github.com/RaguTeam/RAGU获取，Meno-Lite-0.1模型可从https://huggingface.co/bond005/meno-lite-0.1获得。

## Abstract
Graph retrieval-augmented generation (GraphRAG) enhances large language models with structured knowledge, yet existing systems construct knowledge graphs in a single extraction pass, producing noisy entities and brittle retrieval. RAGU, an open-source modular GraphRAG engine, addresses this by separating extraction from consolidation: entities and relations pass through two-stage typed extraction, DBSCAN-backed deduplication, LLM summarization, and Leiden community detection. A key insight motivates a compact extractor: the skills an in-pipeline LLM needs - comprehension, extraction, reasoning over context - are language skills that grow only weakly with model size, unlike factual world knowledge. Accordingly, we train Meno-Lite-0.1, a 7B model optimized for language skills, which outperforms Qwen2.5-32B on knowledge-graph construction (+12.5% relative harmonic mean) and matches it on English GraphRAG tasks. On GraphRAG-Bench (Medical), RAGU retrieves the most complete context at every factoid level (evidence recall up to 0.84 vs. $\leq$0.76) and overtakes HippoRAG2 on synthesis tasks; on multi-hop factoid QA, the apparent HippoRAG2 advantage is shown to be largely an answer-format artifact. RAGU is installable via $\texttt{pip install graph_ragu}$, runs on a single GPU, and is released under MIT. The source code is publicly available at https://github.com/RaguTeam/RAGU, and the Meno-Lite-0.1 model can be obtained from https://huggingface.co/bond005/meno-lite-0.1.

- **研究背景**：图检索增强生成（GraphRAG）通过知识图谱增强大语言模型（LLM）的上下文理解，但现有系统（如LightRAG、HippoRAG2等）采用单次提取（single-pass）构建知识图谱，导致实体噪声多、检索不稳定。
- **核心问题**：如何构建一个更鲁棒、高精度的GraphRAG系统，同时降低对大规模商用LLM的依赖？
- **整体含义**：作者提出“语言技能 vs. 世界知识”假设——在RAG管道中，LLM主要需要理解、提取和基于上下文推理等语言技能，而这些技能随模型规模增长非常缓慢，因此可以用紧凑的小模型替代大模型。基于此，他们开发了开源模块化引擎RAGU和专用7B模型Meno-Lite-0.1，实现了高质量、低成本的GraphRAG。

## 2. 方法论
- **核心思想**：将知识图谱构建中的**提取（extraction）**与**合并（consolidation）**分离，通过多步流水线减少噪声。
- **关键技术细节**：
  - **多步图构建**：
    1. **分块**：三种策略（SimpleChunker、SemanticTextChunker、SmartSemanticChunker）。
    2. **两阶段提取**：先提取实体（基于NEREL模式，29种实体类型），再提取关系（49种关系类型），强制关系的源和目标必须在已验证的实体集合中，消除实体-关系不匹配。
    3. **合并**：对重复实体（按名称+类型分组）进行DBSCAN聚类，再由LLM生成摘要；关系也进行类似合并。
    4. **社区检测**：Leiden层次聚类。
    5. **社区摘要**：LLM生成结构化社区报告（标题、摘要、发现）。
    6. **可选的细化模块**（如移除孤立节点）。
  - **搜索引擎**：提供5种引擎（LocalSearch、GlobalSearch、NaiveSearch、MixSearch、QueryPlanEngine），支持跨编码器重排序和混合检索（Qdrant）。
  - **紧凑模型Meno-Lite-0.1**：基于RuadaptQwen2.5-7B，经过持续预训练（1.3B tokens）和监督微调（50M tokens），专为RAG中的语言技能设计（NEREL提取、多跳QA、查询日志），支持128K上下文，在俄语上分词效率比原始Qwen2.5提高47%。
  - **工程化亮点**：三层存储抽象（图/KV/向量），Pydantic验证结构化输出防止代码注入，异步API，374个测试和确定性模拟LLM服务器实现无API密钥CI。

## 6. 主要结论与发现
- **语言技能假设得到支持**：模型大小对世界知识（CheGeKa）影响显著（F1增长21.1×），但对语言技能任务（MultiQ）影响弱（仅4×），且7B模型Meno-Lite-0.1在KG构建上优于32B模型（调和平均+12.5%），在端到端GraphRAG任务上与更大模型持平。
- **RAGU的合成能力强**：在GraphRAG-Bench的创意生成和覆盖度上超越HippoRAG2，且在所有事实级别上证据召回率最高（0.84 vs. ≤0.76）。
- **HippoRAG2在精确事实检索和多跳链式推理上领先**（如MuSiQue），但多跳问答中部分优势是答案格式假象：统一为直接答案后，RAGU在BioASQ上持平（AC 72.9 vs. 72.4），在2Wiki上差距缩小（58.0 vs. 63.5）。
- **Meno-Lite-0.1可作为紧凑的替代品**：端到端任务中差距<2pp，且节省大量成本（单GPU vs. 更大模型或API）。
- **实用建议**：需要综合上下文的任务（总结、创意生成、长文本问答）首选RAGU；需要精确事实查找和多跳推理的任务首选链式遍历系统（如HippoRAG2）。

## 7. 优点
- **方法论创新**：将提取与合并明确分离，减少噪声，生成更干净的知识图谱。
- **紧凑模型训练**：验证了语言技能与模型大小的弱相关性，训练出7B模型达到32B级别的提取能力，显著降低部署门槛。
- **工程成熟度**：Pydantic验证防止代码注入、异步API保证吞吐、存储抽象便于后端迁移、374个测试和模拟LLM服务器实现无依赖CI，这些是现有开源GraphRAG框架所缺乏的。
- **全面评估**：覆盖多个基准、两种生成协议、消融实验，并揭示了格式假象，结果可信。
- **开源友好**：MIT许可证，pip一键安装，单GPU可运行。

## 8. 不足与局限
- **缩放证据有限**：仅基于Qwen2.5家族和少数任务，假设是强支持的假说而非普适定理。
- **模型限制**：Meno-Lite-0.1的参数量化知识召回能力弱，不能作为独立知识库使用；多跳推理在超过32K tokens后性能退化（7B模型常见现象）。
- **分布重叠风险**：IE基准与微调数据共享NEREL模式和领域，虽然使用了不同文档和词形，但残余优势不能完全排除。
- **扩展性限制**：默认NetworkX后端不适合百万级节点的大规模语料，需替换为专用图数据库。
- **对提取LLM敏感**：弱基础模型会引入结构噪声，合并无法完全矫正。
- **偏差与公平性**：NEREL模式针对俄语新闻文本，用于其他语言或领域需要适配；模型和输出可能继承语料偏见，敏感应用前需领域评估。
- **实验覆盖面**：主要限于英文和俄文，未涉及其他语言或更大规模的工业场景。
