## 摘要
Jupyter Notebooks已在数据科学领域广泛采用，因为它们允许共享可重现的计算分析。然而，只有理解计算机代码的人才能使用它们。为了吸引更广泛的、对数据分析和计算感兴趣但不熟悉代码的科学家，我们引入了Plainbook，这是一种以自然语言而非代码为核心的笔记本。Plainbook基于两个原则：强调自然语言描述，并验证数值。在Plainbook中，自然语言描述被保留，而不是生成的代码；代码是根据单元格描述自动生成的。由于自然语言是从上到下阅读的，Plainbook采用线性执行语义，保证单元格按其出现顺序执行；不存在Jupyter中那样的“隐藏状态”或乱序执行。为了让可能不懂代码的用户能够验证计算的正确性，我们在Plainbook中内置了以数值和数值检查为中心的验证机制。这些机制包括专注于单个单元格的机制（类似于单元测试）以及全局机制。线性执行语义和验证机制都基于一个快照内核，该内核缓存执行状态，使执行和验证高效。

## Abstract
Jupyter Notebooks have become widely adopted in data science, as they allow the sharing of reproducible computational analysis. They are, however, accessible only to people who understand computer code. To reach the broader audience of scientists interested in data analysis and computation, but unfamiliar with code, we introduce Plainbook, notebooks centered on natural language rather than code.   Plainbook is based on two principles: promote the natural language descriptions, and verify the values. In plainbook, the natural language descriptions are preserved, rather than the resulting code; the code is generated automatically from the cell descriptions. As natural language is read top to bottom, Plainbook adopts a linear execution semantics, in which cells are guaranteed to be executed in the order in which they appear; there is no "hidden state" or out-of-order execution as in Jupyter. To allow users who may not understand code to verify the correctness of the computation, we have built into Plainbook verification mechanisms centered on values and value inspection. These include mechanisms that focus on individual cells, akin to unit tests, as well as global mechanisms. Both the linear execution semantics, and the verification mechanisms, are underpinned by a snapshot kernel that caches execution states and makes execution and verification efficient.

## 2. 方法论

- **核心思想**：
  - **提升描述性**：保留并突出自然语言描述作为单元格的主要内容，代码作为自动生成的后台实现，不可见或可选查看。
  - **验证数值**：用户通过检查计算结果（而非代码）来验证正确性，依靠 AI 和系统性测试。
- **关键技术细节**：
  - **线性执行语义**：单元格严格按照从上到下顺序执行，每个单元格执行在上一单元格的状态上，执行一次即定，无“隐藏状态”。执行二次是幂等的。
  - **快照内核**：缓存每个单元格执行后的 Python 命名空间（状态），支持高效重跑特定单元格时无需从头重跑整个笔记本。
  - **代码生成**：向 AI API（如 Claude、Gemini）发送含以下内容的提示：当前单元格描述、先前单元格的描述和代码、前一个状态的变量列表（含类型与 DataFrame 列信息）、可选的前一单元格输出、全局文件路径和领域指令。代码生成后保存，后续修改描述时 AI 仅修订必要部分。
  - **验证机制**：
    - **单元格验证**：用户可请求 AI 检查该单元格代码是否忠实实现其自然语言描述。支持使用与生成不同的 AI 模型交叉验证，防止单一模型中的隐藏后门。
    - **单元格测试**：利用线性语义，用户可在一股并行流程中运行目标单元格，但数据由“数据准备单元格”简化（用自然语言描述简化条件），用户可目测结果或编写验证单元格检查。
    - **全局测试**：通过自动生成的昵称引用不同单元格的状态，编写断言检查跨单元格的关系（如过滤后数据是否保留某些字段）。
  - **编排**：跟踪三个索引（icode: 有效代码最大索引, iout: 有效输出最大索引, iexec: 已执行最大索引），根据编辑、代码生成、执行等操作更新索引，自动计算需重新生成或执行的最小单元格集合。

## 6. 主要结论与发现

- Plainbook 成功让不懂代码的委员会成员能够创建和验证数据分析笔记本，降低了编程门槛。
- 线性执行语义和快照内核使迭代改进单元格变得高效（无需重启全部）。
- 单元格测试通过简化数据，使非程序员能通过目测验证结果正确性，提高了信任。
- 对于熟悉代码的用户，Plainbook 在会议协作中反而更快（减少点击步骤）。

## 7. 优点

- **方法创新**：首次系统提出以自然语言描述为核心的计算笔记本框架，并配套基于值的验证体系，适合非程序员使用。
- **工程实现**：快照内核高效支持线性语义，编排算法自动管理代码再生范围，减少不必要计算。
- **安全性**：支持跨 AI API 验证，可防御针对单一模型的隐藏漏洞。
- **易用性**：自然语言描述可直接编辑，代码生成和验证集成在按钮中，符合直觉。
- **开源**：代码已发布在 GitHub 并可通过 pip 安装，可复现和扩展。

## 8. 不足与局限

- **配置门槛**：用户需自行获取 AI API 密钥并配置计费，对新手不友好。
- **无法跟踪外部状态**：快照内核只保存 Python 命名空间，无法处理跨单元格的文件句柄或数据库事务（如连接后未关闭），导致非幂等行为。
- **代码再生过于保守**：修改早期单元格描述后，Plainbook 会强制再生所有后续单元格的代码，即使多数不需要改动，造成时间和成本的浪费。作者计划未来让 AI 先判断哪些单元格需再生。
- **依赖 AI 能力**：代码生成质量受限于当前 AI 模型，对于复杂语义或罕见库可能出错。
- **实验不足**：缺乏大规模用户研究、定量性能对比（与 Jupyter+AI 基准）和消融实验，结论的泛化性有限。
- **仅支持 Python**：当前实现限于 Python，其他语言（R、Julia）未涉及。
