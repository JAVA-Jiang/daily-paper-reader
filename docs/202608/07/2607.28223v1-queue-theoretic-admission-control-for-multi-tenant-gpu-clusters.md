## 摘要
GPU集群运营商无法预测待处理工作负载等待准入的时间。现有系统使用贪心启发式方法，没有正式的等待时间保证。我们将GPU集群准入形式化为一个多类别、多资源的排队网络，并证明了一个结构性分解：待处理队列分为可配额工作负载（在稳定性下有界等待时间）和不可行工作负载（没有重新配置则无限界）。对于可配额工作负载，我们将每个集群队列建模为M/G/k系统，其中有效服务器数量k由向量打包归约确定；在显式随机占优假设下，我们建立了O(1/(1-rho))的等待时间缩放。我们通过从向量装箱归约证明，在多维资源需求下最优准入排序是NP-hard的。我们在Kueue（标准的Kubernetes工作负载排队系统）上使用CPU、内存和GPU（通过动态资源分配）资源进行验证。向量k_eff正确识别瓶颈资源维度，Little定律精确成立，Erlang-C近似在保守方向上始终高估观察到的等待时间。

## Abstract
GPU cluster operators cannot predict how long pending workloads will wait for admission. Existing systems use greedy heuristics with no formal wait time guarantees. We formalize GPU cluster admission as a multi-class, multi-resource queueing network and prove a structural decomposition: the pending queue partitions into quotable workloads (bounded wait time under stability) and unfeasible workloads (no finite bound without reconfiguration). For quotable workloads, we model each cluster queue as an M/G/k system where the effective server count k is determined by a vector packing reduction; under an explicit stochastic domination assumption, we establish O(1/(1-rho)) wait time scaling. We prove that optimal admission ordering is NP-hard under multi-dimensional resource demands via reduction from vector bin packing. We validate on Kueue, the standard Kubernetes workload queuing system, using CPU, memory, and GPU (via Dynamic Resource Allocation) resources. The vector k_eff correctly identifies bottleneck resource dimensions, Little's Law holds exactly, and the Erlang-C approximation consistently overestimates observed wait times in the conservative direction.

## 一、核心问题与整体含义（研究动机与背景）

- **现实痛点**：GPU 集群利用率极低（行业报告显示企业集群平均利用率仅 5–30%），运营商无法预测待处理工作负载究竟要等待几分钟还是几小时才能获得准入（Admission）。
- **现有方案的缺陷**：生产级批处理排队系统（Kueue、Slurm 及各类私有调度器）均采用贪心准入启发式，**没有任何形式化的等待时间保证**；Kubernetes 的 KEP-168 工作负载可见性提案也明确将等待时间估计排除在外。
- **与已有排队论工作的区别**：近期排队论研究（如 Mitzenmacher 与 Shahout 的学习增强调度、Dai 等人的 LLM 批处理吞吐最优性）针对的是**单个模型部署内部的请求调度**，而非跨多租户集群的工作负载准入；后者面临三大额外困难：
  1. **向量打包**：每个工作负载要求多维资源（GPU 数、显存、CPU、内存、网络带宽），需同时满足所有维度；
  2. **混合队列**：待处理队列同时包含"最终可被准入"与"在当前配置下永远无法准入"两类负载；
  3. **抢占反馈**：被抢占的工作负载重新入队，产生状态相关的到达过程，破坏经典模型的独立到达假设。

## 二、方法论：核心思想、关键技术细节与公式

### 1. 系统形式化定义
- 将 GPU 集群准入系统定义为元组 **S = (Q, F, R, C, W)**：集群队列集合、资源风味（flavor）集合、资源类型集合、容量函数、工作负载类别集合。
- 准入条件为**多维资源向量同时满足**：∀ r ∈ R: d_j(f, r) ≤ Available(q, f, r)。

### 2. 核心定理：可配额/不可行划分定理（Quotable/Unfeasible Partition）
- **可配额（Quotable）**：存在某个 flavor 使需求向量不超过潜在可用容量（PotAvail，含借用上限）——稳定性下等待时间有界；
- **不可行（Unfeasible）**：不满足上述条件，无重新配置则等待时间**无有限上界**。
- **Theorem 1** 证明：任何不区分两类负载的等待时间估计器，期望绝对误差至少为 α·(M − μ_W)，随水平线增长而无界——**划分是低误差估计的必要条件**。

### 3. 有效服务器数 k_eff 的向量打包归约
- 单类别：k_eff(q, j) = max over compatible flavors of min over resources of ⌊C(q,f,r)/d_j(f,r)⌋；
- 多类别：采用**主导资源近似**（DRF 风格），按类别占比 φ_j 加权求最小维度；
- **Proposition 1**：d ≥ 2 维时 k_eff 不超过各维容量算术平均的 1/d，仅当需求向量完全对齐时取等。

### 4. M/G/k 随机占优假设与等待时间界
- **Modeling Assumption 1**：真实系统等待时间 W_real 在随机序意义下被 M/G/k 参考系统（k = k_eff，到达率含抢占反馈 λ_eff = λ + μ_p）占优；该假设的充分条件为：BestEffortFIFO 调度、检查点式或低频抢占、近似泊松到达。StrictFIFO 或从头重启式高频率抢占下假设可能不成立。
- **Theorem 2**：稳定性条件 ρ_q < 1 下，可配额负载期望等待时间有限。
- **Theorem 3**：在 FCFS + 有限 (2+ε) 阶矩服务时间下，E[W_q] = **O(1/(1−ρ))**（基于 Li 与 Goldberg 的多服务器 Kingman 界）。
- **实用近似（Modified Erlang-C，Cosmetatos-Tijms 近似）**：
  - Ŵ_q = Erlang-C 概率 C(k,ρ) × [E[S]/(k(1−ρ))] × [(C_S²+1)/2]；
  - 可纳入抢占反馈（ρ_eff = (λ+μ_p)·E[S]/k）与 Cohort 借用（k_eff⁺ 含期望借用容量）。

### 5. 计算复杂性刻画
- **Proposition 2**：固定 MIG profile 集合 + 一维资源 + 无拓扑约束时，问题可多项式求解；
- **Theorem 4**：多维资源需求（d ≥ 2）下 GTAP（GPU 拓扑感知准入）NP-hard，由 d 维向量装箱归约；
- **Corollary 2**：最优准入排序（最小化总加权等待时间）NP-hard——**硬度来源是多维向量打包，而非 MIG 分区**。

## 三、实验设计：数据集、场景与对比方法

- **验证平台**：Kueue v0.19.0（Kubernetes 标准工作负载排队系统），4 节点 kind 集群（1 控制平面 + 3 工作节点，Kubernetes 1.36）。
- **工作负载生成**：泊松到达间隔 + 指数服务时间（均值 20s），每任务请求 500m CPU + 64Mi 内存；目标利用率 ρ 从 0.3 扫到 0.92，每个利用率水平提交 80 个任务。
- **场景一（CPU/内存排队验证）**：单 ClusterQueue，2 CPU 配额，k_eff = 4；验证 Little 定律与 Erlang-C 预测精度。
- **场景二（向量打包验证）**：非对称配额（4 CPU + 2Gi 内存），工作负载请求 500m CPU + 512Mi 内存，得到标量 k_eff^CPU = 8 与向量 k_eff = 4，对比两者预测效果。
- **场景三（GPU 资源验证）**：通过 DRA（Dynamic Resource Allocation）接入模拟 GPU 驱动（dra-example-driver），3 节点各 8 个 GPU，配额 4 GPU + 8 CPU + 8Gi 内存，每负载 1 GPU + 500m CPU + 256Mi 内存，k_eff^GPU = 4，k_eff^CPU = 16。
- **对比方法**：无历史数据的 Erlang-C 模型预测 vs. 有历史数据的 EMA（指数移动平均，α=0.3）基线（后者用于对比点预测精度；独立实验中 64 个负载、15s 平均服务时间、ρ≈0.9）。
- **划分非空性验证**：注入 5% 超过潜在可用容量（20 CPU vs 2 CPU 配额）的负载，观测到挂起负载中 50% 落入 Kueue 的 inadmissible 集合（作为不可行划分的上界）。

## 六、主要结论与发现

1. **划分必要性**：不区分可配额/不可行负载的任何等待时间估计器都会产生无界误差——这是论文最核心的理论贡献。
2. **等待时间标度律**：可配额负载在稳定条件下满足 E[W] = O(1/(1−ρ))，即等待时间与容量裕量成反比增长。
3. **复杂度刻画**：多维资源下的最优准入排序 NP-hard；MIG 固定 profile 打包多项式可解——硬度源于维度而非 GPU 分区。
4. **向量 k_eff 正确识别瓶颈**：标量 CPU-only 估计（k=8 或 16）完全遗漏内存/GPU 瓶颈，预测等待时间接近 0；向量 k_eff=4 正确识别瓶颈维度，预测高估 33%–4.3×（保守方向）。
5. **Erlang-C 一致保守**：在中低利用率（ρ_obs = 0.27–0.95）下高估观测等待时间 2.3–18×，作为**先验上界**有用，但作为点预测器过松。
6. **EMA 基线点预测更准**（MAE 6.8s vs Erlang-C 18.2s），但 Erlang-C 的优势在于**无需历史观测**，适用于容量规划。
7. **Little 定律精确成立**（比值 1.000），证明排队模型与 Kueue 实际行为内部一致。

## 七、优点与亮点

- **理论贡献扎实**：首次为 GPU 集群准入控制建立形式化等待时间界；可配额/不可行划分定理给出了清晰的必要性与构造性证明。
- **复杂度刻画精准**：通过命题 2 与定理 4 的对照，精确定位了 NP-hard 的根源（多维向量打包），而非普遍认为的 GPU 分区问题。
- **模型具有实用性**：所有模型参数均可从现有 Kueue/Prometheus 指标导出（论文给出完整映射表），并考虑了抢占反馈、Cohort 借用、优先级类别等生产特性。
- **"保守方向"验证严谨**：明确区分了"经验上保守的估计"与"证明的上界"，并诚实指出随机占优是假设而非证明（含失效条件的讨论）。
- **实验设计巧妙**：非对称配额实验（CPU vs 内存/GPU 瓶颈对照）直接验证了多维 k_eff 的核心价值；Little 定律作为内部一致性检查增强了结果可信度。
- **坦率的局限性说明**：对泊松到达、AFS、并发准入、未建模特性（TAS、弹性任务等）均有明确交代。

## 八、不足与局限

- **实验规模与真实性**：仅 3 个工作节点的本地 kind 集群、合成泊松负载；未在真实生产集群或大规模集群上验证；GPU 为模拟驱动而非真实硬件。
- **核心假设未获正式证明**：M/G/k 随机占优（Modeling Assumption 1）仅是合理性论证 + 经验验证；作者自承在 StrictFIFO 或高频率重启式抢占下可能不成立，且无正式耦合构造。
- **预测精度不足**：Erlang-C 高估 2.3–18×，过松而无法作为点预测器；高利用率（ρ>0.95）下公式失效，而该区域恰恰是运营商最关心的。
- **未覆盖的理论特征缺乏实证**：MIG 分区、NVLink 拓扑约束、Cohort 借用、优先级类别、抢占反馈等论文中建模的特性均未在实验中验证。
- **公平性局限**：AFS 开启时 FCFS 假设被违反，模型不适用；并发准入（ConcurrentAdmission alpha 特性）未纳入模型。
- **到达率测量的近似**：用准入吞吐量近似到达率，饱和状态下会低估真实到达率。
- **方法对比单一**：仅对比 EMA 基线，未与其他排队模型、ML 预测方法（如 Lu 等人的工作）或实际调度器启发式比较。
