## 摘要
历史图书藏集中包含丰富的视觉元素——例如插图、照片、版画和装饰艺术——这些元素在大型数字化项目中往往未被充分探索。虽然光学字符识别（OCR）已经标准化了文本内容的提取，但这些视觉组件提供的信息层次和上下文在很大程度上仍未通过自动化文本提取流程得到利用。本技术报告介绍了“机构藏书——视觉元素”，一种用于从历史图书藏集中检测、分类、去重和生成标题的开源端到端流水线。除了该流水线，我们还发布了一个初始数据集，其中包含从构成“机构藏书：哈佛图书馆”数据集的983,004卷扫描卷中提取的2260万个视觉元素。这项工作推动了社区范围内正在进行的努力，通过计算访问为数字化图书馆藏集赋能新的用例，从人工智能模型训练到数字人文学科研究。

## Abstract
Historical book collections contain rich visual elements - such as illustrations, photographs, engravings, and decorative art - that are frequently under-explored in large-scale digitization projects. While Optical Character Recognition (OCR) has standardized the extraction of textual content, these visual components offer a layer of nuance and context that remains largely untapped by automated text extraction workflows. This technical report introduces Institutional Books - Visual Elements, an open-source end-to-end pipeline for detecting, classifying, deduplicating, and captioning visual elements from historical book collections. Alongside this pipeline, we release an initial dataset of 22.6 million visual elements extracted from the 983,004 scanned volumes that comprise the Institutional Books: Harvard Library dataset. This work contributes to ongoing, community-wide efforts to enable new use cases for digitized library collections through computational access, from artificial intelligence model training to digital humanities research.

- **研究动机**：数字化图书项目（如 Harvard Library 的 Google Books 藏集）虽已通过 OCR 标准化了文本提取，但其中的视觉元素（插图、照片、版画、装饰、图表、乐谱等）仍被大规模忽视。现有 Vision-Language Models (VLMs) 的训练数据以互联网当代视觉内容为主，在处理历史内容时会出现性能退化、年代误判、文化错位等问题。
- **核心问题**：如何构建一个**可复现、可扩展、且在普通知识机构可负担的算力范围内**的自动化流程，用于从近 100 万卷扫描书中提取、分类、去重和生成标题视觉元素。
- **总体含义**：以开源流水线 + 2260 万视觉元素数据集的形式，为 AI 模型训练和数字人文学研究提供基于历史材料的计算访问途径，旨在缩小模型对历史视觉内容理解的空白，并推动图书馆/机构在文化遗产数据上的大规模计算利用。

## 2. 论文提出的方法论：核心思想、技术细节与流程

该流水线采用**模块化的端到端架构**，核心设计原则是"从最小可行的干预出发，仅在必要时升级计算开销"（frugal computing）。具体步骤及关键技术如下：

### 2.1 检测（Detection）
- **模型选择**：YOLO26n（2.4M 参数，CNN 单类检测器），因为历史页面具有强归纳偏置，CNN 比 VLM 在算力和精度上更适合。
- **训练数据**：4,528 页图像（271 册），6,103 个边界框标注，包含负样本；最终训练/验证/测试集按 80/10/10 划分；检测目标被简化为单类二分任务（定位与分类解耦）。
- **推理设置**：输入图像分辨率 640×640、置信度阈值 0.3（追求高召回）、NMS IoU 阈值 0.2（保留密集且空间接近的视觉元素）。
- **输出**：每个检测框附带坐标、置信度和来源文件名。

### 2.2 分类（Classification）
- **模型选择**：YOLO26s-cls（2.8M 参数），实现五类分类：Image/Illustration、Music、Artifact（扫描错误/手指/夹子等）、Ex Libris/Decorative、Chart/Graph。
- **训练数据**：6,042 个 crops，经人工+中间模型预标注并人工修正；训练使用了多种增强策略（颜色抖动、几何变换、mosaic、RandAugment、随机擦除）。
- **推理设置**：输入 640×640，仅对含检测结果的页面解码，避免额外 I/O。
- **后处理**：对低置信度（<0.70）的预测重新标记为 "Other"；针对 Music 类，结合置信度阈值（≥0.99）和多语言关键词过滤进行重分类（约 12,502 项被改为 "Other"）。

### 2.3 去重（Deduplication）
采用**两阶段互补策略**，兼顾效率和精度：
- **感知哈希（pHash）**：12×12 DCT-based 144-bit 哈希，使用 Hamming 距离阈值 τ=16 判断近似重复。为避免 O(n²) 复杂度，采用 **banding-style LSH**（B=6 个 band，每 band 24 bits），外部排序后并行计算候选对的 Hamming 距离，并用 Union-Find 聚簇。
- **语义嵌入（SSCD）**：使用 Self-Supervised Copy Detection (SSCD) 模型（ResNet-50 + GeM pooling，24.6M 参数），输出 512 维 L2 归一化嵌入。使用 **FAISS HNSW** 索引（12 connections，cosine 距离阈值 0.14，即相似度 ≥0.86）进行近似最近邻查找。
- **最终策略**：仅保留**哈希分组与嵌入分组一致**的元素作为重复组，每个组内选取检测置信度最高的代表作为唯一保留项（保守去重，19.6% 的减少率）。

### 2.4 实验性 LLM 辅助生成标题（Captioning）
- **模型选择**：OpenAI GPT-4.1-nano（外部 API 调用，非本地 GPU）。
- **输入**：系统提示 + 页面 OCR 文本上下文（用于语义锚定）+ 图像 crops（最大维度 1248px，base64 编码）+ 源语言提示。
- **输出**：标题文本 + token 级 logprobs + 检测到的语言 + 与 Chronicling America 种族/民族关键词词表的朴素匹配计数。
- **设计特点**：明确标注为"实验性"（`_exp`），且排除 Ex Libris/Decorative 和 Artifact 类（因其缺乏语义内容）；生成标题使用源卷语言。

### 2.5 方向校正（Orientation Correction）
- **模型选择**：EfficientNet-V2-M（52.8M 参数），四分类（0°/90°/180°/270° 校正）。
- **训练数据**：7,904 个 crops 经人工校正为直立后，合成旋转出 4 个样本，共 31,616 样本（训练/验证/测试：25,292 / 3,160 / 3,164），同源旋转样本保留在同一划分中以防止污染。
- **推理策略**：仅应用于 Image/Illustration 和 Chart/Graph 类；部署时置信度阈值设为 0.99，低于此阈值则不旋转（因绝大多数页面本就直立，假阳性成本更高）。

3. **分类分布**：Image/Illustration 占 68.0%，其次为 Artifact (9.2%)、Ex Libris/Decorative (7.0%)、Chart/Graph (6.2%)、Music (5.3%)；分类器平均置信度极高（0.966，中位数 1.000）。
4. **数据集的系统性偏差**：视觉元素数据集比文本语料更集中于 19–20 世纪（64% + 33%）、英语（60%）、以及视觉密集学科（Science、Fine Arts），而 Law、拉丁语等纯文本领域显著代表性不足——这反映了历史出版实践和学科惯例，而非哈佛藏集的固有比例。
5. **SSCD 优于通用多模态编码器**：在近重复检测中，专门为复制检测设计的 SSCD 模型显著优于 CLIP/SigLIP/OpenCLIP 等通用视觉语言编码器。
6. **检测瓶颈在数据 I/O 而非 GPU 计算**：检测阶段 GPU 利用率仅约 47%，89.5% 的时间花在图像解码和预处理上；分类阶段则是 GPU 计算主导（55.7% 时间用于推理）。

## 7. 优点

- **开源且模块化**：流水线全部开源，各步骤可独立重运行、可替换模型和阈值，降低了知识机构的采用门槛。
- **节俭计算原则**：明确记录并公开了算力足迹，包括与 DGX Spark 的对比运行，有利可复现性。
- **严格的数据溯源与透明性**：数据字段带 `_src`（源数据）、`_gen`（生成）和 `_exp`（实验）后缀，清晰区分了直接搬运自原始材料的数据与 AI 生成/实验性数据，有助于用户识别"可信"数据。
- **高质量的文档与伦理考量**：包含详细的数据集字段说明、附录中的各类分布、对有害语言/内容的明确免责声明、权利状态判断的透明说明。
- **实验设计中的细节处理**：如分类时保存完整 softmax 分布而非仅最大值、去重时选择哈希/嵌入交叉策略的保守取向、方向校正中针对偏差（大部分页面已直立）设计的非对称置信度阈值。
- **对 VLM 应用于历史内容问题的批判性反思**：基于初步实验，论文坦诚地指出了现有 VLM 在历史图像方向校正、内容安全评估等任务中的不足，并提供了后续研究方向。

## 8. 不足与局限

- **计算流程瓶颈明显**：检测阶段 GPU 利用率仅 47%，主要受 CPU 端解码和 I/O 限制，未来优化空间大；检测作为整个流水线的入口，其遗漏（假阴性）会传递到所有下游阶段。
- **生成标题的质量风险**：作者明确承认 VLM 可能产生看似合理但事实上错误的描述（幻觉）；针对历史图像的上下文，现有通用安全模型并不适用；且未提供定量质量评估。
- **数据集系统性偏差**：视觉元素数据集偏向 19–20 世纪、英语、视觉密集型学科；若用户不加批判地使用，会导致模型过度泛化这些时期和领域的视觉文化，作者也明确指出这一点。
- **版权与权利状态不确定性**：虽仅纳入 HathiTrust 标记为公共领域的卷，但作者承认公共领域判断存在复杂性和跨境差异。
- **语言覆盖不足**：Lingua 语言识别器支持语言范围有限，生成标题的语言匹配率仅报告为 1.5% 的不匹配，但这一指标本身不可靠。
- **方向校正的局限性**：测试集基于合成旋转，对真实历史扫描中常见的非标准旋转和页面扭曲的稳健性未知；推理阈值 0.99 会保留大量实际需要校正但未处理的图像。
- **去重的保守性**：仅采用哈希与嵌入交集，可能遗漏被单一信号识别出的重复内容（假阴性），实际重复率可能高于报告值。

## 结语

该论文是数字图书馆计算访问领域的一项实质性贡献，以开源方式提供了完整的视觉元素提取流水线和大规模数据集，并在工程细节、数据透明性和伦理合规方面表现出色。它的主要短板在于：对历史视觉内容的 LLM 生成标题仍属探索性质，缺乏严格质量评估；数据集存在固有的时间/语言/学科偏差；以及检测阶段 I/O 瓶颈限制了端到端效率。尽管如此，该工作为

该工作为数字人文学科与计算机视觉的交叉研究奠定了可复用的基础设施，为后续在历史图像理解、跨文化视觉语义建模、以及图书馆大规模计算服务等方向的研究提供了重要的数据和工具起点。若未来能在以下方向推进，其价值将进一步提升：用更严格的人工评估框架校验标题生成质量、引入更高效的 I/O 管线以释放 GPU 算力潜力、并在更多机构藏集上验证流水线的泛化能力。总体而言，它在工程完整性、数据透明性和节俭计算理念上的实践，为文化遗产的大规模计算利用树立了一个值得参照的范式。
