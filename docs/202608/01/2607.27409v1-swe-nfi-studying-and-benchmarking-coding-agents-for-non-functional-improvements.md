## 摘要
尽管编码智能体在面向正确性的基准测试中表现令人瞩目，但其进行保持行为不变的非功能性改进（NFI）的能力仍未得到充分探索。在现实世界的软件开发中，开发者不断改进软件质量而不改变可观察行为，然而现有基准主要评估功能正确性，对评估这些非功能性改进的支持有限。本文提出了SWE-NFI，一个在功能正确性之外评估编码智能体NFI能力的基准。我们的基准包含188个任务，这些任务源自开源Python项目中真实合并的拉取请求。我们将面向开发者的NFI操作化为92条可执行规则，并开发了一套综合评估套件，将功能正确性测试与基于规则的NFI评估相结合。我们评估了最先进的商业和开源编码智能体。尽管表现最佳的智能体达到了70.0%的功能正确率，但所有被评估的智能体在整体NFI能力上普遍逊于人类开发者。这一差距在结构性代码改进方面尤为明显，智能体的NFI得分范围为0.0至1.3，而人类参考得分为1.5。我们的基准和发现为在功能正确性之外评估和推进编码智能体提供了一个可复现的基础。

## Abstract
Although coding agents have achieved impressive performance on correctness-oriented benchmarks, their ability to make behavior-preserving non-functional improvements (NFIs) remains underexplored. In real-world software development, developers continuously improve software quality without changing observable behavior, yet existing benchmarks primarily evaluate functional correctness and provide limited support for assessing these non-functional improvements.   In this paper, we present SWE-NFI, a benchmark for evaluating coding agents on NFIs beyond functional correctness. Our benchmark contains 188 tasks constructed from real merged pull requests in open-source Python projects. We operationalize developer-oriented NFIs into 92 executable rules and develop a comprehensive evaluation suite that combines functional correctness testing with rule-based NFI evaluation.   We evaluate state-of-the-art commercial and open-source coding agents. Although the best-performing agent achieves a 70.0\% functional correctness rate, all evaluated agents generally fall short of human developers in overall NFI capability. The gap is particularly evident for structural code improvements, where agents' NFI scores range from 0.0 to 1.3, compared with 1.5 for the human reference. Our benchmark and findings provide a reproducible foundation for evaluating and advancing coding agents beyond functional correctness.

# SWE-NFI：编码智能体非功能性改进能力的研究与基准测试

## 1. 论文的核心问题与整体含义

**研究动机与背景**：

- 现有编码智能体基准（如 SWE-bench、HumanEval、MBPP 等）几乎全部聚焦于**功能正确性**，即能否通过单元测试或实现预期功能。
- 真实软件开发和维护中，开发者大量进行**行为保持的非功能性改进（NFI）**，如改进文档、错误处理、安全性和可维护性、升级库用法、改善代码风格、简化程序结构等——这些改动不改变可观察行为，但对软件的长期演进至关重要。
- 一个功能正确的解决方案可能仍然存在文档糟糕、异常处理不当、库使用过时或结构过于复杂等问题。仅用功能正确性评估编码智能体，无法反映其实际部署中的真实价值。
- 论文提出 **SWE-NFI** 基准，将非功能性改进操作化为可执行规则，系统性地填补了这一空白。

## 2. 方法论：核心思想与关键技术细节

**总体架构**：SWE-NFI 采用三阶段流水线（如图 1 所示）：

**阶段一：NFI 规则定义（92 条可执行规则）**

- 遵循 SWE-IF 的五个 NFI 高层维度：文档（Documentation）、错误处理（Error Handling）、库约束（Library Constraints）、编码风格（Coding Style）、逻辑模式（Logic Patterns）。
- 规则来源三管齐下：① 2020-2025 年间软件工程和 AI 顶会论文（筛选出 35 篇高相关论文）；② GitHub 高星 Python 仓库的 issue 讨论（326 条高参与度 issue）；③ Python 官方编码规范（PEP 8/257/3134/484/585）及权威技术标准。
- 规则分为两大类：
  - **确定性规则（24 条）**：可被静态分析直接验证，分为"必须遵守"（Required）和"禁止出现"（Prohibited）两种，用二元指标衡量。
  - **阈值型规则（21 条）**：需要与预设阈值比较，如函数最大长度、圈复杂度 ≤10、嵌套深度 ≤3、魔法数字数量等。
- 表 1 显示规则分布：Deterministic 24 条、Threshold-based 21 条（表格中各项相加应为 92 条，含 Required/Prohibited/Quantitative 三类）。

**阶段二：任务构建（188 个任务）**

- 从 GitHub 上 100 个生产级 Python 仓库（星数 ≥45,000，中位数 66,254）收集 2020-2025 年合并的 PR，去除机器人、依赖更新、发布类 PR 后获得 226,955 条原始记录。
- 用 NFI 评分公式过滤出 6,775 条正向改进记录（211,914 条无可测量变化、7,566 条为回归、700 条为评分器错误）。
- 自动过滤 + 两位作者人工验证（Cohen's κ=0.71），最终保留 484 条验证实例，再经筛选得到 188 个最终任务（145 单文件 + 43 多文件）。
- 人工构造任务描述，隐藏 PR 最终改动和参考实现，避免信息泄漏。

**阶段三：评估套件**

- 每个任务配有手工实现的单元测试（人工参考实现全部通过验证）+ 基于规则的 NFI 评估（使用 Ruff、Radon、AST 分析和自定义脚本）。
- 评估完全自动化，不依赖 LLM-as-a-judge 或人工标注。

**核心公式**：

- 归一化规则得分： S_p(c) = P_p(c) / T_p（某方面 p 中代码版本 c 满足的规则数 / 规则总数）
- NFI 改进量： I_p(c_before, c_after) = S_p(c_after) − S_p(c_before)（正值=改进，零=无变化，负值=退化）
- 评估对象： I_{i,p}(x) 表示来源 x（人类或智能体）在方面 p 上的改进量，与同一个 code_before 比较。

## 3. 实验设计

**基准与数据集**：SWE-NFI 基准包含 188 个真实世界任务（145 单文件 + 43 多文件），全部来自真实合并 PR，反映开发者日常进行的非功能性改进。

**对比模型（8 种配置）**：

- 商业智能体：OpenAI Codex（gpt-5.3-codex）、Claude Code Agent（claude-sonnet-4-6）
- 开源智能体：Aider 和 mini-SWE-agent，各自搭配三个基础模型：gpt-4.1、gemini-2.5-flash、deepseek-chat

**实验协议**：每个智能体配置在全部 188 个任务上重复执行 5 次（temperature 设为 0 以获得稳定性），报告平均结果。人类参考实现仅用于计算人类参考改进，不暴露给智能体。

**输出有效性过滤**：先检查有效输出率（非空+可解析语法），再执行单元测试确认功能正确性，仅对"有效且功能正确"的输出进行 NFI 评分。

**四个研究问题（RQ）**：
- RQ1：与人类参考改进对比的 NFI 表现
- RQ2：任务范围（单/多文件）的影响
- RQ3：重复执行的稳定性与一致性
- RQ4：执行时间与 Token 消耗的实际成本

## 4. 资源与算力

- **论文未明确说明使用的 GPU 型号、数量和训练时间**，也未提供硬件配置细节。
- RQ4 提供了丰富的**运行时成本和 Token 消耗数据**（每种配置各有约 940 次有效运行）：
  - **Claude Code Agent** 成本最高：平均每轮 14,330 秒、5,074 万 Token

**实验规模**：
- 8 种智能体配置 × 188 个任务 × 5 次重复，总运行约 7,520 次
- 每个 RQ 从不同维度对结果进行系统分析

**充分性评估**：
- 优点：全面覆盖商业/开源多类智能体，多模型对比设计合理；重复实验减少了随机性影响；人工验证提升基准质量。

## 6. 主要结论与发现

**RQ1（总体表现）**：当前编码智能体在 NFI 方面显著落后于人类开发者
- 功能正确率最高为 Claude Code Agent 的 70.0%，但各 NFI 维度全面低于人类参考
- **逻辑模式（Logic Patterns）差距最大**：所有智能体得分 0.0-1.3，人类为 1.5——结构性代码改进是当前智能体的最大短板
- 文档和错误处理是智能体最强维度（部分配置超过人类，如 Aider+GPT-4.1 文档 8.1 vs 人类 8.0）
- Mini-SWE 系配置的功能正确率瓶颈（4.8%-11.5%）严重限制了其 NFI 表现

**RQ2（任务范围）**：
- 多文件任务整体上比单文件任务更具挑战性
- 文档改进在多文件任务中偶有提升（如 Claude Code Agent 6.9→9.3），但错误处理和逻辑模式一致性地在多文件任务中退化（Codex 逻辑模式从 1.5 降至 0.4）
- Mini-SWE+GPT-4.1 和 Mini-SWE+Gemini 2.5 在多文件任务上完全无法产出功能正确结果

**RQ3（稳定性）**：NFI 改进在重复执行中相对稳定（最好配置标准差 ≤0.4），波动主要出现在有效输出率和功能通过率阶段；高一致性不等于高有效性。

**RQ4（成本）**：计算成本差异跨数量级且与 NFI 表现不呈比例关系。

## 7. 亮点与优点

1. **开创性角度**：首次系统性地将 NFI 作为编码智能体评估维度，弥补了纯功能正确性评估的盲区。
2. **规则可执行性强**：将抽象的高层质量维度操作化为 92 条确定性可计算规则，实现完全自动化、确定性、可复现的评估，不依赖 LLM-as-a-judge（相比 SWE-IF 是重要进步）。
3. **基准数据真实**：全部任务源自真实合并 PR，反映开发者实际维护行为，且设计防信息泄漏机制（隐藏最终补丁和参考实现）。
4. **综合评估体系**：功能正确性测试与 NFI 规则评估结合，先筛选"有效+功能正确"输出再评价 NFI 质量，逻辑严谨。
5. **多文件任务覆盖**：包含 43 个多文件任务，比现有基准更贴近真实仓库级开发。
6. **丰富的数据分析**：4 个 RQ 覆盖 NFI 表现、范围影响、稳定性、成本四个维度，呈现较为完整的图景。
7. **详尽的规则来源**：从学术文献、真实开发讨论、编码规范三个互补来源交叉验证规则有效性。

## 8. 不足与局限

1. **语言单一化**：只研究 Python，结论无法推广到其他编程语言（作者在威胁有效性中已承认）。
2. **规则覆盖有限**：92 条规则无法捕捉软件质量的全部维度（如性能、安全、可访问性、可用性等），部分质量维度如性能无法用静态分析完全衡量。
3. **内部有效性风险**：任务描述的手工构建和人工验证过程可能存在主观偏差；单元测试覆盖可能不完整（输出"通过测试"不严格等价于"行为完全保持"）。
4. **智能体覆盖有限**：仅 8 种配置，未涵盖所有最新发布的前沿编码智能体；基础模型更新很快，结论时效性有限。
5. **计算成本考量不足**：论文没有报告自身构建基准和运行实验的硬件开销细节，读者难以复现完整实验。
6. **任务数量相对较小**：188 个任务相对于 SWE-bench 等大规模基准（数千任务）规模偏小，可能影响统计功效。
7. **NFI 度量粒度粗**：二元规则和简单计数的方式可能无法区分改进的"质量差异"（如文档写得"好"与"足够"都算满足规则）。
8. **无消融实验**：缺少对规则阈值选取、规则类型（必需 vs. 禁止 vs. 阈值）等设计选择的敏感性分析。
9. **人类参考的局限**：PR 中的实际改动记录了"开发者做了什么"，但不一定是理论上的最优 NFI，以它为参考基准存在一定任意性。
