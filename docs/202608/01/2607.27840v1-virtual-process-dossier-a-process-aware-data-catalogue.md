## 摘要
我们提出了虚拟流程档案（VPD），一种基于知识图谱的数据目录，同时也捕获工作流溯源。我们为多阶段制造用例开发了VPD，在这些用例中，下游基于AI的优化任务需要区分在单个工作流步骤中生成的数据集。VPD以FAIR方式提供这些数据集，并明确展示前瞻性和回顾性工作流溯源。我们的贡献包括：(1) VPD本体，作为目录的语义核心；(2) VPD溯源框架，将本体实例化集成到生产环境中；(3) VPD用户界面，提供与VPD知识图谱的人本交互。本体和代码可在 https://github.com/kubeluk/VirtualProcessDossier 获取。

## Abstract
We propose the Virtual Process Dossier (VPD), a Knowledge Graph-based data catalogue that also captures workflow provenance. We developed VPD for multi-stage manufacturing use-cases where downstream AI-based optimization tasks require to distinct between datasets generated during individual workflow steps. VPD provides these datasets in a FAIR manner and makes both prospective and retrospective workflow provenance explicit. Our contributions are: (1) the VPD ontology that serves as the catalogue's semantic core; (2) the VPD provenance framework that integrates ontology instantiation into the production environment; and (3) the VPD user interface that provides human-centered interaction with the VPD Knowledge Graph. The ontology and code are available at https://github.com/kubeluk/VirtualProcessDossier .

## 2. 方法论：核心思想、关键技术细节

### 2.1 总体思路
- **VPD的定位**：一个位于原始数据源层之上的"知识层"（knowledge layer），以知识图谱为核心，语义化增强存储在外部系统中的传感器观测数据，使其满足 FAIR 原则。
- **核心思想**：将制造流程视为工作流，通过显式建模**前瞻性（prospective）**和**回顾性（retrospective）**工作流溯源，将传感器数据集与其生成过程中的具体步骤、设备、参数进行语义关联。

### 2.2 VPD本体（VPD Ontology）
- **本体工程方法**：与流程工程师、机械工程师和数据科学家开展多轮工作坊，提取能力问题（Competency Questions），据此选择并复用现有标准化本体。
- **本体构造**：轻量级对齐（alignment）从 4 个既有本体出发：
  - **DCAT**（描述数据集、分布与访问机制）
  - **WiLD**（描述前瞻与回顾性工作流溯源，基于树形结构支持顺序、并行等语义）
  - **PROV**（描述实体、活动、代理之间溯源关系）
  - **SSN/SOSA**（描述传感器与观测）
  - 仅引入少量新类用于对齐，如 `vpd:SensorActivity`、`vpd:MachineActivity`、`vpd:Product`、`vpd:Parameterization`。
- **三个核心视角**：
  1. **传感器与数据集**：通过 `vpd:SensorActivityInstance` 作为 `wild:ActivityInstance` 和 `sosa:Observation` 的子类，将 WiLD 的活动实例与 SOSA 观测关联，从而可描述数据的生成过程。
  2. **机器与参数**：引入 `vpd:Machine`（同时作为 `prov:Agent` 和 `sosa:FeatureOfInterest`），并利用 PROV 的资格模式（Qualification Pattern）量化关联机器参数化（`vpd:Parameterization`），参数值采用 QUDT 本体表示。
  3. **产品与材料**：`vpd:Product` 与 `vpd:Material` 作为 `prov:Entity` 子类，通过 `prov:Derivation` 关联工作流实例。

### 2.3 VPD溯源框架（VPD Framework）
- **阶段一：设置与初始握手（Setup and Initial Handshake）**——生产前
  1. 实例化 `dcat:Catalog`，铸造全局唯一 IRI 标识符
  2. 为环境中每个机器和传感器实例化 IRIs（`Mi`、`Sj`）
  3. 为被观测属性赋予 `sosa:ObservableProperty` 的 IRI（`Ok`）
  4. 用 WiLD 词汇描述制造工作流（`wild:WorkflowModel`）
  5. 将 IRI 元组（`Al`，`Mi`）和（`VPD`，`Sj`，`Ok`）分发到各控制器——确保每个物理执行者拥有全局可识别名称并知道其执行的活动名称
- **阶段二：最终握手与执行（Final Handshake and Execution）**——生产时
  - 创建新的工作流实例 IRI（`WI`）并发布到各控制器，完成"握手"同步
  - 制造系统以分布式、开环方式运行，通过直接发送 SPARQL/Update 查询向知识图谱实时插入溯源信息
  - **传感器执行**：捕获数据集 D 的 IRI、创建 `dcat:Dataset` 并关联 `prov:wasGeneratedBy` 指向传感器活动实例，后续再发布 `dcat:Distribution`（含 `dcat:downloadURL`）
  - **机器执行**：与传感器流程类似，捕获关联参数化信息
- **阶段三：回顾性增强（Retrospective Augmentation）**——生产后
  - 为未自动化捕获的信息（如人工观察、未实现的过程）手动补充溯源信息。

### 2.4 VPD用户界面（VPD UI）
- 技术栈：基于 SHACL 形状自动生成 HTML 表单（利用 shacl-form 库），支持用户注册生产运行、浏览搜索数据集、导航和可视化工作流溯源。

- VPD 是一种基于知识图谱、流程感知的数据目录方案，通过本体层、框架层和交互层三层架构完整覆盖制造数据的 FAIR 化管理需求。
