## 摘要
大语言模型（LLMs）的快速崛起推动了企业在转型中的广泛采用。然而，由于复杂的系统约束和意外的用户行为，在真实场景中部署这些模型面临独特的挑战。在这些应用中，槽位填充对于将非结构化输入转换为结构化、可操作的数据至关重要。在这项工作中，我们介绍了ESF-Bench，一个具有挑战性的企业槽位填充基准，包含8个独特领域的810个多轮样本和6530个槽位。根据在企业实际部署中观察到的57个最具挑战性的槽位填充场景的分类标准，ESF-Bench揭示了当前最先进的LLMs的显著局限性，其中GPT-OSS-120b仅在20.7%的基准样本中成功提取槽位。为了支持该领域的持续研究，我们在GitHub上公开发布了基准数据集、分类标准和随附的评估代码。

## Abstract
The rapid rise of large language models (LLMs) has driven transformative adoption across enterprises. However, deploying these models in real-world settings presents unique challenges due to complex system constraints and unexpected user behaviors. Among these applications, slot filling is essential for converting unstructured input into structured, actionable data. In this work, we introduce ESF-Bench, a challenging Enterprise Slot Filling benchmark consisting of 810 multi-turn samples and 6530 slots over 8 unique domains. Curated using a taxonomy of the 57 most challenging slot-filling scenarios observed during real-world enterprise deployments, ESF-Bench exposes notable limitations in current state-of-the-art LLMs, with GPT-OSS-120b low successfully extracting slots for only 20.7% of benchmark samples. To support continued research in this area, we publicly release the benchmark dataset, taxonomy, and accompanying evaluation code on GitHub.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）在企业级 AI 助手中的应用日益普及，槽位填充（Slot Filling）是将非结构化用户输入转化为结构化、可操作数据的关键能力，广泛用于 IT 服务管理（ITSM）、客户服务（CSM）、IT 运维（ITOM）、HR、金融、医疗、法律、教育等领域。
- **问题**：现有槽位填充基准（如 MultiWOZ、SGD、SNIPS、ATIS、MASSIVE 等）主要面向传统任务型对话或单句理解，侧重于抽取式槽位，未能覆盖企业真实部署中的复杂约束、多源上下文和意外用户行为（如模糊表述、矛盾信息、条件语句、相对值依赖、修正与重置等）。
- **挑战**：真实企业场景中，槽位值可能存在依赖关系、冲突来源、优先级规则、归一化要求、复杂推理需求；用户行为常常模糊、矛盾、带讽刺或需纠正，这些都会显著降低 LLM 的实际提取准确率。
- **研究目标**：构建一个能反映真实企业槽位填充难度的基准 ESF-Bench，系统评估当前 SOTA LLM 的能力差距，并发布数据集、分类体系和评估代码以推动后续研究。

## 2. 方法论（核心思想、关键技术细节）

- **核心思想**：以“人类标注的挑战场景分类体系（taxonomy）”为驱动，合成生成多轮、多源、多领域的企业槽位填充测试样本，并对每个槽位标注其所属场景，从而支持细粒度能力诊断。
- **槽位填充分类体系（Taxonomy）**：包含 **57 种场景**，划分为 **12 个高层类别**：
  - Selection（选择）：枚举值选择、比较、最高级、否定、歧义指定、菜单选择等。
  - Conditionals（条件）：if 条件、if-else 条件决定是否填充或取值。
  - Reasoning（推理）：数学推理、时间推理、计数、条件计数、常识推理。
  - Multi-Source（多源）：多跳推理、源优先级规则处理冲突信息。
  - Long/Multi-Value（长/多值）：长 ID/URL/序列号、多值槽位及约束过滤。
  - Conversation Understanding（对话理解）：跨轮引用、反问句、助手提议确认、元讨论等。
  - Personalization（个性化）：基于用户画像定制，以及画像不匹配的对抗场景。
  - Schema Constraints（模式约束）：默认值、归一化规则、正则/语法约束、单位要求、跨槽约束等。
  - Unexpected User Behavior（意外用户行为）：不确定、模糊、讽刺、双重否定、拼写错误、提及第三方实体等。
  - Relative（相对值）：槽位值相对其他槽位定义，基槽更新时需隐式传播。
  - Corrections（修正）：显式/相对/条件修正、反向修正、违反约束的修正。
  - Slot Reset（槽位重置）：单个槽或全部槽重置、条件重置、撤销重置。
- **数据合成流程**：
  1. 从 taxonomy 中随机采样场景组合；
  2. 通过一系列 LLM 调用生成提示词组件及其元数据（模式、对话、知识库文章、用户画像、会话信息、表单等）；
  3. 用独立的 LLM 调用基于相同元数据生成 ground truth，并由 judge 模型验证正确性；
  4. 使用 GPT-5 作为生成和评判模型，GPT-4.1 用于场景标注；
  5. 每个槽位被标注对应的 taxonomy 场景，支持细粒度分析。
- **输出格式转换**：由于槽位填充的输出格式无统一标准，论文利用 LLM 自动生成 Python 函数，将各提示词的不同输出结构映射为统一格式以进行标准化评估。
- **评估指标**：提出 **Final Joint Goal Accuracy（F-JGA）**，与逐轮 JGA 不同，它只评估最终对话状态是否与 ground truth 完全一致，适用于任务无关的端到端和离线评估。同时报告**带标签槽位准确率**（仅针对有 taxonomy 标注的槽位，占 66.8%）以及**响应 token 数中位数**（含推理轨迹）。

## 3. 实验设计

- **基准数据集**：ESF-Bench，包含 **810 个多轮对话样本**、**6530 个槽位**，覆盖 **8 个领域**（ITSM、CSM、ITOM、HR、金融、医疗、法律、教育），每个领域有 25 个具体实例，共 200 个领域-实例组合。
- **样本内容**：每个样本包含合成的任务导向 schema、用户-助手对话，以及辅助来源（知识库文章、用户画像、会话信息、历史表单），要求模型跨来源整合信息。
- **对比模型**：
  - 5 个模型家族：GPT-5.1、Gemini 2.5 Flash、GPT-OSS-120b、Qwen3-32b、Ministral3 14b。
  - 每个模型在两种配置下评估：
    - **High-Capability（高能力）**：启用完整推理，如 GPT-5.1/GPT-OSS 高推理、Gemini 2.5 Flash 动态思考、Qwen3 思考模式、Ministral3 reasoning 变体。
    - **Low-Latency（低延迟）**：关闭或降低推理，如 GPT-5.1 minimal、Gemini 无思考、Qwen3 无思考、GPT-OSS 低推理、Ministral3 instruct。
- **评估方式**：在全部 810 样本上报告 F-JGA、tagged slot accuracy、中位 token 数；并按 taxonomy 类别和具体场景进行细粒度准确率对比。
- **人类基线**：在 122 个带标签槽位的代表性子集上，人类标注者完成槽位填充任务，获得 F-JGA 73.33% 和 Tagged Slot Accuracy 93.83%。

## 6. 主要结论与发现

- **总体表现**：即使是最好模型 Gemini 2.5 Flash Dynamic-Thinking 也只有 33.3% 的 F-JGA，GPT-OSS-120b Low 仅 20.7%；人类 F-JGA 为 73.33%，存在巨大差距。
- **推理模型优势显著**：高能力（推理）模型在 F-JGA 和 tagged slot accuracy 上分别平均提升 +16.3% 和 +13.4%，尤其在推理（+32.1%）、相对值（+20%）、条件（+17.8%）类别上优势明显。

- **高能力模型的特殊失败模式**：
  - 无法识别第三方实体引用，错误提取他人信息作为用户槽值；
  - 对讽刺性表述按字面理解；
  - 对双重否定产生混淆；
  - 面对用户画像不匹配时仍错误利用画像填充槽位；
  - 在缺少单位时仍生成带单位的槽值。
- **低延迟模型的短板**：几乎无法完成多步推理、跨轮信息聚合、条件判断等复杂场景。
- **开源模型表现**：GPT-OSS-120b High 与最佳专有模型差距仅 -4.4% tagged slot accuracy，且在长/多值和模式约束上领先；Qwen3-32b-Think 在多源、个人化、相对槽位上表现最佳；但在 UUB、推理和 F-JGA 上落后专有模型。
