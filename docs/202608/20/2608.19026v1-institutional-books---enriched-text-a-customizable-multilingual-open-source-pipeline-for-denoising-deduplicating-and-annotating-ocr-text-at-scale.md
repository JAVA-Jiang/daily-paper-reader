## 摘要
《机构藏书：哈佛图书馆》（IB-HL）于2025年发布，是一个包含983,004卷（2420亿个o200k_base tokens）的馆藏，最初通过哈佛图书馆参与谷歌图书图书馆项目进行数字化。随着研究人员和开发者开始使用IB-HL，标准的大规模预处理实践与谨慎的信息管理目标之间出现了矛盾。许多现有流水线针对网络文本进行优化：因此，它们往往激进地过滤、去重、按语言限制，有时还会丢弃有意义的元数据。与此同时，希望使用IB-HL的研究人员在执行类似的处理和分析时重复劳动。我们描述了一种称为“增强文本”（Enriched Text）的方法。我们不是生成单一的“完整”token流，而是通过标注规范化文本，同时保留元数据。我们分离书末内容，检测每个段落的语言，识别重复段落的聚类，并计算每个段落的每字节比特数得分。我们通过叠加在文本上的类HTML标注提供这些信息。通过解析这些标注，用户可以根据自己的需求定制输出，而不是接受对内容的全局编辑决策。该流水线适用于馆藏中所有约250种语言。本报告描述了该项目的目标、实现和设计原理。此次发布包括IB-HL-ET（IB-HL的增强文本版本，包含983,003卷中的2170亿个o200k_base tokens，组织为13.9亿个带标注的子主题段落）以及生成该版本的流水线。这些使得该馆藏更易于机器解析和人工研究。

## Abstract
Released in 2025, Institutional Books: Harvard Library (IB-HL) is a collection of 983,004 volumes (242B o200k_base tokens), originally digitized through Harvard Library's participation in the Google Books Library project. As researchers and developers have begun to use IB-HL, a tension has emerged between standard large-scale preprocessing practices and the goals of careful information stewardship. Many existing pipelines optimize for web text: as a result, they tend to aggressively filter, deduplicate, restrict by language, and sometimes discard meaningful metadata. Meanwhile, researchers seeking to use IB-HL duplicate effort while performing similar processing and analysis.   We describe an approach that we call Enriched Text. Instead of producing a single 'complete' stream of tokens, we normalize the text while preserving metadata through annotations. We separate endmatter, detect per-paragraph language, identify clusters of duplicate paragraphs, and compute per-paragraph bits-per-byte scores. We provide this information through HTML-like annotations layered on top of the text. By parsing these annotations, users can tailor the output to their own needs instead of accepting a global editorial decision on content. The pipeline applies to all $\approx$250 languages in the collection.   This report describes this project's goals, implementation, and design rationale. The release includes IB-HL-ET (an enriched-text version of IB-HL containing 217B o200k_base tokens across 983,003 volumes, organized into 1.39B annotated subtopic paragraphs) and the pipeline that produced it. These serve to make the collection easier for machines to parse and for humans to study.

  - 现有流水线多针对网络文本优化，倾向于**激进过滤、激进去重、按语言筛选**，并经常丢弃有意义的元数据。

- **总体思路**：与其生成单一的"干净"token流，不如将元数据与文本结构**以注解形式叠加在文本上进行保留**，让用户根据自身需求自行过滤，从而兼顾规模化处理与信息保真。

## 2. 方法论

论文提出了一种称为 **"Enriched Text"（增强文本）** 的处理范式。核心思想是**标注而非删除**：将语言学内容与副文本分离，把结构信息和元数据编码为类HTML标记，用户可通过解析这些标记自由定制输出。

处理流水线（依次执行）包括如下关键步骤：

- **预处理与设置（§4.1）**：将98万卷按卷内主语言分组为shards（最多200卷/组）；为约250种语言训练n-gram语言模型（1~5 gram）；为138种NUPUNKT兼容语言训练基础分词模型；使用Model2Vec将BAAI/BGE-M3蒸馏为静态嵌入模型，并微调为endmatter分类器和子分类器。
- **Unicode规范化（§4.2）**：采用两套规范化方案——"软规范化"（输出用，保留可见文本，NFC归一化、去除零宽空格）和"硬规范化"（仅内部使用，NFKC折叠、标点统一、展平为单行）。
- **重复页面移除（§4.3）**：基于9-gram的128位simhash，Hamming距离≤6即视为近似重复，通过union-find聚类并删除重复页面。
- **Endmatter分离（§4.4）**：使用静态分类器将每卷分为frontmatter、middlematter、backmatter；子分类器将endmatter进一步标记为TOC_INDEX、BIBLIO或OTHERENDMATTER。分类器基于GPT-OSS-20B合成的多语言训练数据（15万条，筛选后约4.45万有效）微调而来。
- **去连字符（§4.5）**：对行末连字符，通过add-k平滑（k=0.001）的字符n-gram语言模型（结合基础语言模型与卷内专属模型），配合Stupid Backoff算法，对三种候选方案（合并、保留连字符、替换为空格）进行概率排序，选取最优。
- **页眉页脚移除（§4.6）**：针对每页上下各5行，用MinHash LSH（Jaccard阈值0.85）检测5页范围内重复≥3次的短行并删除。
- **页码移除（§4.7）**：检测每页顶部/底部5行中长度≤8字符、含至少一个Unicode数字类字符的行并删除。
- **句子分割（§4.8）**：对138种NUPUNKT兼容语言（占97.9%的书籍），使用NUPUNKT（每卷单独自适应训练）；其余112种语言使用SAT-3L-SM（Segment-any-Text）神经分割模型，这是在GPU上运行的唯一环节。
- **主题分块（§4.9）**：对每个句子计算静态嵌入（Model2Vec蒸馏的BGE-M3），以相邻各5句的均值嵌入余弦相似度作为gap分数，采用TextTiling算法的valley-depth方法检测语义边界，生成**subtopic paragraphs**（平均5.08句/段）和**subtopic sections**（约4.69段/节）。
- **重复段落识别（§4.10）**：对约14亿段落计算硬规范化+小写化的9-gram simhash（128位），Hamming距离≤5视为重复；将签名分为6个band（22/21/21/21/21/22位）进行LSH分桶，用排序+线性扫描找候选桶，并以union-find聚类。重复段落**不删除**，仅通过`<aside data-cluster>`注解标记。
- **每字节比特数BPB（§4.11）**：使用Qwen/Qwen3-0.6B-BASE计算每段落的BPB（以UTF-8字节数为分母的交叉熵归一化），并提供卷内各百分位统计（p10、p30、median、p70、p90等）。过长/过短段落用-1哨兵值标注。
- **最终注释与格式化（§4.12）**：以类HTML格式输出frontmatter_gen、middlematter_gen、backmatter_gen三个字段，包含`<section>`、`<p>`、`<aside>`标签及data-bpb、data-language、data-clusterid、data-representative等属性；额外计算21项卷级元数据字段（语言分布、token数、n-gram统计、可token化率等）；另提供一份已过滤的纯文本版本processed_middlematter_gen作为基线。

## 6. 主要结论与发现

- **"标注而非删除"的可行性与价值**：通过分层注解，用户可自由定制输出，而无需重新处理语料；剥离标签即得纯文本，保留标签即可获得结构、语言、重复和质量等多维信息。
- **可大规模复现**：整套流水线绝大多数步骤可在CPU上运行，单台DGX Spark约一个月可复现（BPB除外），证明"节俭计算"与高质量语料处理可以兼容。
- **清洗效果显著**：相比IB-HL原始OCR文本，IB-HL-ET的bigram唯一率从46.40%降至38.79%，trigram唯一率从74.46%降至69.23%，tokenizability从80.43提升至86.57，表明噪声有效降低。
- **多语言可操作性**：流水线覆盖约250种语言；段落级语言检测与卷级主语言标注的一致率达98%，差异主要出现在双语卷或n-gram高度重叠的语言对（如德-意第绪-荷兰语、奥克-加泰罗尼亚语等）。
- **重复文本的主要来源**：英语重复率最高（8.09%），反映了英语子语料的规模效应；超大型重复聚类多为表格噪声（"do. do."、"……"等）或漏网的图书馆刻板条款标记。
- **BPB随时间递减**：卷级中位BPB从17世纪的≈2.5降至19世纪中叶的≈1.4、20世纪中叶的≈1.0，反映现代语言模型对近代文本更可预测；但该趋势混杂了OCR噪声和样本构成的变化。
- **现有流水线的已知局限**：数学公式和表格中连字符可能被错误合并（改变语义）；反复出现的脚注引用可能被误判为页脚而删除；对竖排文字语言的页眉页脚检测准确率较低。

## 7. 优点

- **理念先进且务实**：以"标注而非删除"作为核心哲学，既保留信息保真度，又不牺牲可用性和灵活性，是对现有网络文本预处理范式的重要纠偏。
- **技术选型审慎且可复现**：大量使用C++扩展（simhash、MurmurHash3）和静态嵌入模型（Model2Vec）降低计算门槛；几乎全程CPU可运行，计算成本可控。
- **多语言覆盖广**：约250种语言，包括低资源语言；针对NUPUNKT不兼容语言专门设计SAT分流策略，并以数据驱动决定阈值。
- **设计决策均有数据支撑**：每个环节的改进工具、参数选择（如n-gram长度、Hamming距离阈值、F1=0.6的划分标准）都有明确的实验依据或概率分析。
- **透明度和可审计性好**：详细记录了所有阶段的耗时、统计量、错误样例和已知局限；提供合成训练数据、完整流水线代码和解析器库等多种资源。
- **下游应用空间大**：重复段落被标记而非删除，可直接用于研究文本传播、跨语言引用和印刷史；BPB注释允许用户按相对标准过滤，而非强制全局截断。

## 8. 不足与局限

- **端到端影响未直接评估**：论文未量化不同过滤/去重选择对下游模型训练效果（如困惑度、下游任务准确率）的实际影响，缺乏与现有流水线的系统性对比实验。
- **OCR质量依赖性**：该流水线不重新OCR，完全依赖已有OCR输出；表格、数学公式和密集排版内容仍处理不佳，且这些缺陷会逐级传递到后续注释中（已知示例见附录D）。
- **语言检测存在偏差**：短段落上的语言检测精度下降；小段落中被误判为丹麦语或葡萄牙语的比例异常偏高；对某些低资源语言可能产生系统性偏差。
- **BPB的语义模糊性**：BPB混淆了模型意外度（surprise）与OCR噪声，对低资源语言和罕见书写系统可能产生误导性高分；且以现代语言模型作为参考时，无法公平衡量历史文本的可预测性。
- **计算瓶颈**：BPB计算需约83个GPU天，是整体复现的主要障碍，可能限制其他机构对该步骤的复现。
- **分类器依赖合成数据**：endmatter分类器依赖GPT-OSS-20B合成训练数据，子分类器准确率为0.90，存在对部分语言和排版风格泛化不足的潜在风险。
- **局限的已知后处理副作用**：例如页眉页脚去除算法可能删除较长的重复脚注/引文（如K. und k. Kriegs-Archiv案例从137处降至64处），去连字符在数学文本中会改变语义。这些反映了"自动清洗"与"信息保真"之间的固有张力。
- **版权与内容风险**：尽管仅收录公有领域卷目（HathiTrust标记），但版权判定可能出错；语料包含历史上的冒犯性语言和偏见内容，需谨慎使用。
