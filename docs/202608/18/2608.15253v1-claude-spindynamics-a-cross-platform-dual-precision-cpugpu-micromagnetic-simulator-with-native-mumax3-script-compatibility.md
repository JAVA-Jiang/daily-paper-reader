## 摘要
定量自旋电子学日益依赖于少数GPU微磁代码，这些代码均需NVIDIA硬件并全程使用单精度，导致没有此类硬件的研究人员甚至无法运行标准验证问题。我们报告了Claude-SpinDynamics（Claude-SD），一款新的开源微磁模拟器，具有跨平台C++20核心（Windows和Linux）和Python接口，弥补了这一差距：完整的CPU构建，通过与GPU路径相同的测试套件验证，无需任何加速器即可运行所有单元测试和uMAG标准问题；GPU构建则提供单精度和双精度，两种退磁FFT后端可选，并原生实现自旋轨道、自旋转移和Zhang-Li力矩，Dzyaloshinskii-Moriya相互作用以及逐晶格材料。Claude-SD原生解释mumax3的.mx3脚本语言，因此现有社区脚本无需修改即可运行；在匹配条件下，两种代码在逐单元基础上与单精度舍入一致，并且与mumax+和OOMMF一起，在uMAG动态切换标准问题上误差在2%以内，而MuMax-CO在同一问题上与mumax3达到float32舍入一致。与这三种代码进行正面基准测试，Claude-SD的单精度构建在小型和二维问题上是最快的求解器，并在最大网格尺寸上保持竞争力，而其双精度和双FFT后端路径在GPU微磁代码中无与伦比。GPU副本批处理扩展进一步在每一步的单次内核启动中推进整个有限温度轨迹集合，与逐试验循环相比，吞吐量提高一至两个数量级，同时将单轨迹结果复现到数值舍入精度。完整源代码采用开放许可，并附带可运行的示例笔记本和文档，以便独立复现。

## Abstract
Quantitative spintronics increasingly depends on a handful of GPU micromagnetic codes, all of which require NVIDIA hardware and single precision throughout, leaving researchers without such hardware unable to run even the standard validation problems. We report Claude-SpinDynamics (Claude-SD), a new open source micromagnetic simulator with a cross platform C++20 core (Windows and Linux) and a Python interface that closes this gap: a complete CPU build, validated by the same test suite as the GPU path, runs every unit test and uMAG standard problem with no accelerator at all, alongside GPU builds offering both single and double precision, a choice of two demagnetization FFT backends, and natively implemented spin-orbit, spin-transfer, and Zhang-Li torques, Dzyaloshinskii-Moriya interaction, and percell materials.Claude-SD natively interprets mumax3's .mx3 scripting language, so existing community scripts run unmodified; under matched conditions the two codes agree cell-by cell to single-precision round-off, and, together with mumax+ and OOMMF, to within 2% on the uMAG dynamic-switching standard problem, with MuMax-CO agreeing to mumax3 to float32 round-off on the same problem. Benchmarked head-to-head against these three codes, Claude-SD's single-precision build is the fastest solver on small and two-dimensional problems and remains competitive at the largest grid sizes, while its double-precision and dual-FFT-backend paths are unmatched among GPU micromagnetic codes. A GPU replicabatching extension further advances an entire ensemble of finite-temperature trajectories in a single kernel launch per step, giving one to two orders of magnitude of throughput over a per-trial loop while reproducing single-trajectory results to numerical round-off. The complete source is openly licensed and distributed with runnable example notebooks and documentation for independent reproduction.

  - 原生兼容mumax3的.mx3脚本语言，降低社区迁移成本；
  - 在性能上与现有顶级GPU代码竞争，并在特定场景实现超越。

### 二、方法论：核心思想、关键技术细节与算法流程

#### 1. 总体架构
- **C++20 核心**：采用窄接口设计（`IEffectiveField` / `ISpinTorque` / `integrator`），每个物理项同时具备 float64 CPU 参考实现和（可选）CUDA GPU 实现；
- **Python (pybind11) 接口**：提供五种运行方式：
  - CPU 库（无需加速器）；
  - GPU 四变体：{float32, float64} × {cuFFT, VkFFT}；
- **跨平台**：Windows/MSVC 与 Linux/GCC 均可编译运行。

#### 2. 物理与数值方法
- 求解 Landau–Lifshitz–Gilbert (LLG) 方程：

  dm/dt = -γ′μ₀(m × H) - γ′αμ₀ m × (m × H)，其中 γ′ = γ₀/(1+α²)

- **有效场贡献**：Zeeman、单轴/立方/表面各向异性、六点拉普拉斯交换作用（Neumann或周期边界）、开路退磁（Newell张量FFT卷积）、周期退磁（镜像和核）、体/界面DMI、RKKY层间耦合、磁弹各向异性；
- **自旋力矩**：Slonczewski STT、自旋轨道力矩（SOT）、Zhang–Li力矩，按积分器阶段逐级加入；
- **有限温度**：Stratonovich-Heun 随机LLG格式 + cuRAND热噪声场，或副本批处理 Depondt–Mertens 方案。

#### 3. 与 mumax3 物理约定的精确对齐
- 界面/体DMI符号、斯格明子极性约定、自由边界条件均遵循 Rohart–Thiaville 约定（与 mumax3 一致，无符号重映射）；
- 唯一文档化差异：Zhang–Li 漂移速度约定（无 Thiaville 的 1/(1+ξ²) 预因子），但提供选项可精确匹配 mumax3。

#### 4. 副本批处理（Replica Batching）引擎
- 在磁化状态前添加一个前导副本维度 R，每个核函数（旋转更新、交换/单轴/Zeeman场、退磁、热噪声）在单次内核启动中推进全部 R 条轨迹；
- 每条轨迹携带独立的电流密度 J 和温度 T；
- 热噪声使用基于计数器的 Philox 流，按 (seed, replica, step) 键控，实现统计独立且位可复现；
- R=1 时与单轨迹参考积分器在数值舍入范围内一致；
- 可选 retire/refill 机制：轨迹满足停止条件时冻结，空出的槽位用新鲜噪声流重新激活。

### 六、主要结论与发现

1. **CPU 构建完整可用**：Claude-SD 的 CPU 路径无需任何加速器即可运行全部单元测试和 μMAG 标准问题，对无 GPU 的开发/教学场景意义重大；
2. **与 mumax3 精确一致**：在匹配条件下，两代码逐单元一致到单精度舍入（DMI 边缘倾斜相对差异 5×10⁻⁷）；SP#4 动态切换标准问题上与 OOMMF/mumax+/mumax3 均吻合在 2% 以内；
3. **小/2D 问题性能领先**：Claude-SD 单精度 cuFFT 构建在 SP#4 网格上比 mumax3 快 5.3×、比 mumax+ 快 14×；在 ≈0.1–0.5M 单元以下区间最快；
4. **大网格竞争性**：540K 单元时与 mumax3 的差距在 1.57× 以内，2.5M 单元时在 1.14× 以内；
5. **双精度成本可接受**：float32 比 float64 快 4–6×（大 3D 网格），但双精度能力是其他 GPU 微磁代码没有的；
6. **VkFFT 与 cuFFT 互补**：VkFFT 在大规模 float64 变换上超越 cuFFT，小网格上落后；
7. **副本批处理带来数量级加速**：核心吞吐量提升 55–160×，端到端（含 Python 驱动开销）从 ≈2.5 h 降至 ≈0.6 s；
8. **网格收敛的物理洞察**：STT 切换阈值仅在网格尺寸低于交换长度（ℓ_ex = 4.89 nm）时收敛；10 nm 网格偏低约 25%；
9. **松弛算子影响跨代码一致性**：匹配动态积分器类型时相图一致性达 92%，而阻尼松弛 vs 共轭梯度仅 53–56%——松弛算子本身是所比较物理的一部分。

### 七、优点与亮点

1. **跨平台 + CPU/GPU 双路径**：彻底打破 NVIDIA 硬件锁定，无 GPU 用户也能运行全部验证；

### 八、不足与局限

1. **大网格吞吐量不及 mumax3 家族**：作者坦承，大规模 float32 生产仍是 mumax3 家族的领域，Claude-SD 的优势集中在小型/2D 问题；
2. **阻尼松弛收敛慢**：对刚性 DMI 纹理，damped-LLG 松弛器收敛慢于自适应最小化器，拓扑荷研究建议使用能量最小化器或加大步长预算；
3. **.mx3 解释器覆盖面有限**：仅支持实际使用的子集，非 mumax3 全部脚本 API（用户指南附录有明确清单与原生 API 替代方案）；
4. **副本批处理退磁核未优化**：使用全复数（非对称压缩）张量收缩，简单且正确，但大规模时非内存最优形式；
5. **HIP 后端未经 AMD 实机验证**：仅通过 HIP-over-CUDA 验证编译和运行，原生 AMD/Intel 性能未实测；
6. **基准仅在 NVIDIA GPU 执行**：AMD/Intel GPU 的对比数据缺失；
