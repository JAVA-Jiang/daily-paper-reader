# REAP : Relation-Aware Elicitation and Parsing for Closed-Book Knowledge Base Construction from LLMs 

Thanh-Dan Bui Thanh-Trung Do Tuan-Phong Nguyen 

VNU University of Engineering and Technology, Hanoi, Vietnam 

{23020342, 24022472, tuanphong}@vnu.edu.vn 

Abstract 

We present the R EAP system for the AKBC Shared Task 2026 on constructing knowledge bases from language models in a closed-book setting, subject to a budget of at most 32B pa-rameters and no model fine-tuning. Our system combines structured chain-of-thought reason-ing, relation-specific query strategies, and a reasoning-based empty-set gate to elicit para-metric knowledge, followed by direct extrac-tion into valid JSON arrays. On the official test set, the system, built on Mistral-Small-24B-Instruct-2501, achieves a macro-F1 score of 0.62 , with particularly strong results on 

countryLandBordersCountry (F1 = 0 .95 ), 

companyTradesAtStockExchange (F1 =0.73 ), and hasArea (F1 = 0 .77 ). Our code is publicly available. 1

1 Introduction 

Large language models (LLMs) encode substan-tial factual knowledge in their parameters (Petroni et al., 2019). However, eliciting this knowledge for knowledge base construction (KBC) is consid-erably more challenging than answering isolated factual questions: a subject–relation pair (s, r ) may correspond to an empty ( ∅), single-valued ( 1), or multi-valued ( N ) object set. The AKBC Shared Task 2026 (Kalo et al., 2026) formalizes this prob-lem under a constrained setting: systems must op-erate in a closed-book fashion, without retrieval-augmented generation or external knowledge; use at most 32B parameters; and perform no model fine-tuning. In this task, each input record specifies a sub-ject entity and one of the six given relations (see Table 1), and the system must return the complete set of corresponding objects as a valid JSON array. The relations cover geographic adjacency and area,

Earlier factual probing methods use cloze-style prompts or prompt ensembles to rank candidate ob-jects (Petroni et al., 2019; Jiang et al., 2020), while the LM-KBC challenge series additionally requires systems to materialize variable-cardinality answer sets (Singhania et al., 2022; Kalo et al., 2023, 2024, 2025). A direct generative solution that asks the model to recall all objects and produce correctly formatted JSON in a single pass can therefore hal-lucinate objects, omit valid answers, or violate the output schema. To address this issue, we propose REAP 

(Relation-aware Elicitation And Parsing), a two-stage pipeline that decouples factual elicitation from answer serialization. Stage 1 prompts the LLM using strategies tailored to each relation, whereas Stage 2 uses deterministic JSON pars-ing when possible and LLM-based extraction only as a fallback. This separation allows the model to focus on recalling the answer set before the system enforces the required JSON format. Our main contributions are as follows: 1. Relation-Aware Elicitation : We design spe-cialized strategies for different relation types, including CoT reasoning with an empty-set gate, a four-direction geographical scan for land borders, and chronological multi-pass querying for awards. 2. 2 Related Work 

Probing knowledge in language models. 

LAMA (Petroni et al., 2019) established cloze-style probing but assumes exactly one object per relation, and what can be extracted depends heavily on the prompt (Jiang et al., 2020); see AlKhamissi et al. (2022) for a survey. The LM-KBC challenge series (Singhania et al., 2022; Kalo et al., 2023, 2024, 2025) recast this as knowledge base con-struction with arbitrary-cardinality object sets ( 0, 1,or N ), the setting continued by the AKBC Shared Task 2026 (Kalo et al., 2026). Prior systems pair LLM probing with entity mapping (Zhang et al., 2023); most recently, ReWiSe (Albert-Roulhac and Zouaq, 2025), a top-performing system at LM-KBC 2025, combines chain-of-thought (CoT) reasoning with relation-wise self-consistency. In R EAP , we adopt the idea of relation-specific CoT and explicit empty-set handling, but drop self-consistency voting, which is costly and can be dominated by confident-but-incorrect reasoning chains. 

Parametric knowledge and its limits. Closed-book QA shows that language models can an-swer factual questions without retrieval (Roberts et al., 2020), motivating the closed-book setting we adopt. This parametric knowledge is uneven, how-ever: models recall popular facts well but struggle with long-tail entities (Kandpal et al., 2023; Mallen et al., 2023), which bounds any closed-book system and matches our error analysis on rare subjects. 

Step-by-step reasoning and empty-set gate. 

Chain-of-thought prompting (Wei et al., 2022; Ko-jima et al., 2022) improves multi-step reasoning and builds on the in-context learning ability of instruction-tuned LLMs (Brown et al., 2020). Since a correct answer may itself be the empty set, in REAP , we add a reasoning-based empty-set gate in-spired by selective prediction (Kamath et al., 2020). Unlike calibrated methods that estimate whether a model knows an answer (Kadavath et al., 2022), our gate is a prompt-driven decision that returns an empty set as the final answer when the property does not exist or the evidence of it is insufficient. 

3 Method 

3.1 Architecture Overview 

The R EAP system consists of two sequential stages (Figure 1). In Stage 1, we use an LLM to gen-erate evidence as free-form text for multi-valued relations or use CoT reasoning for single-valued relations. If the generation phase produces un-parsable output, the system automatically retries or switches to a fallback prompt. Stage 2 extracts 

the evidence into JSON arrays using regular ex-pressions; for multi-valued relations that cannot be handled reliably by simple rules, the LLM per-forms the extraction itself.

Stage 1 prompts are specialized per relation following three principles: (i) query decom-position to maximize recall on multi-valued relations (e.g., six decade-scoped passes for

Together, these relation-tailored, multi-step CoT procedures constitute the structured reasoning that Stage 1 performs before extraction. Few-shot demonstrations are static exemplar pairs (one positive, one empty-set case) fixed per relation to illustrate the reasoning chain and empty-set triggering. Crucially, all exemplars are drawn exclusively from train.jsonl or hand-written triples, ensuring zero data leakage against the eval-uation splits. 

awardWonBy : Chronological Multi-Pass. For major awards with dozens or hundreds of recip-ients, a single query typically yields low recall. We therefore use a multi-pass strategy comprising one general prompt and five auxiliary prompts decom-posed chronologically: from the award’s inception through the 1970s, the 1980s–1990s, the 2000s– 2010s, 2020 onward, and a final pass targeting less prominent or non-Western recipients. All six gen-erations use temperature T = 0 .7 to diversify recall before the evidence is merged. 

countryLandBordersCountry : Four-Direction Geographical Scan. The prompt instructs the model to act as a geography expert and inspect the subject’s eastern, western, southern, and northern boundaries. This scan reduces omissions of small neighboring countries and adjacent detached terri-tories. The prompt includes land borders only, ex-plicitly excludes maritime boundaries, and returns 

BORDERS: NONE for island countries. If the re-sponse lacks the BORDERS: marker, the system au-tomatically retries with a shorter fallback prompt. 

companyTradesAtStockExchange : Four-Step Listing Check. The model follows a four-step CoT procedure: (1) identify the company; (2) ap-ply a Strict Public Check (empty-set gate) to determine whether the entity is a private company, a nonprofit organization, or a subsidiary that is not separately listed, returning FINAL_ANSWER: [] 

if any condition holds; (3) retrieve all listing ex-changes using their full official names, such as New York Stock Exchange or SIX Swiss Exchange ; and (4) conclude with FINAL_ANSWER: ["Exchange Name"] .

hasArea : Four-Step Entity Disambiguation and Unit Normalization. The model follows four CoT steps: (1) distinguish the target entity (e.g., an island, lake, or region) from the country containing it; (2) retrieve its area from parametric knowledge while preserving decimal precision; (3) convert the value to km 2; and (4) output an integer or decimal value as FINAL_ANSWER: ["Value"] .

hasCapacity : Four-Step Reasoning with Capacity-Range Verification. The model fol-lows four CoT steps: (1) determine the venue type and location; (2) distinguish a university or small local stadium from a larger national stadium with a similar name or in the same city; (3) check the estimate against a plausible capacity range (1,000 –35 ,000 seats for small venues and 35 ,000 –

100 ,000 for large national stadiums); and (4) re-turn the capacity as an integer in FINAL_ANSWER: ["Value"] .3personHasCityOfDeath : Five-Step Reasoning with Empty-Set Gate. The model performs five steps: (1) check the subject’s biographical status and record “ALIVE TODAY” if appropriate; (2) resolve name ambiguity; (3) retrieve the city or town of death; (4) isolate the place name; and (5) return FINAL_ANSWER: [] if the person is alive or the information is unavailable, or FINAL_ANSWER: ["CityName"] if the place of death is confirmed. 

3.3 Post-processing 

To ensure that extracted outputs adhere to the ground-truth format, we apply the following auto-mated post-processing procedure after the genera-tion phase: 1. Direct Parsing and Robust Array Extrac-tion : The system directly parses the con-tent of the FINAL_ANSWER: line or recovers a truncated JSON array using balanced-bracket scanning. 2. Numeric Extraction and Normalization :For quantitative relations (hasArea and 

hasCapacity ), regular expressions extract in-teger or floating-point values while removing thousands separators and measurement units. 3. Title and Noise Filtering : For awardWonBy ,the system removes year prefixes (e.g., "1938: Albert Einstein" ), HTML tags, work-title suf-fixes, and honorifics such as Dr. , Prof. , Sir ,

Dame , Lord , Saint , St. , and Mr. to obtain nor-malized entity names. 4. Parenthetical Filtering and Deduplica-tion : The system removes trailing parenthet-ical qualifiers (e.g., "Guinea (West Africa)" 

→ "Guinea" ) and performs case-insensitive deduplication while preserving the capitaliza-tion of the first occurrence. 

4 Experiments 

4.1 Experimental Setup Data. The organizers provide training, valida-tion, and test splits for six relations. The validation and test splits each contain 475 records: 68 for 

countryLandBordersCountry in validation (67 in test), 97 and 98 for hasCapacity respectively, 10 for awardWonBy , and 100 for each of the other three relations. Each record consists of a subject, a re-lation, and a set of objects, each accompanied by a list of aliases. The data cover all three cardinal-ity cases: empty sets (e.g., New Zealand for land borders), single-valued relations, and multi-valued relations (e.g., Nobel Prize in Physics, 229 recipi-ents in train.jsonl , or AAAI Fellow, 350 people in val.jsonl ). 

Models. We evaluate three instruction-tuned models—Gemma-2-9B-it (Gemma Team, 2024), Llama-3.1-8B-Instruct (Llama Team, Meta AI, 2024), and Mistral-Small-24B-Instruct-2501 (Mis-tral AI, 2025)—and compare against the orga-nizer’s Qwen3.5-9B baseline (Qwen Team, 2026). Gemma-2-9B-it and Llama-3.1-8B-Instruct serve as comparison systems, while Mistral-Small-24B-Instruct-2501 (hereafter Mistral-24B) is the pri-mary model in our final system. 

Hardware and Runtime. Experiments are con-ducted on Kaggle using a TPU v5e-8 with eight TPU v5e cores. We serve the models with vLLM TPU Server and use bfloat16 precision. With di-rect parsing and batched inference, one complete run over all six relations in the validation set (475 records) takes approximately 2–5 minutes with 

batch_size=32 .

Metrics. We report macro/micro precision, recall, and F1 using the organizer-provided 

evaluate.py script. For string-valued relations, the evaluator normalizes predictions and matches aliases through maximum bipartite matching. For quantitative relations, it applies a relative tolerance of 5% . Overall macro-F1 is the mean of the per-record F1 scores.

5 Ablation Study 

To quantify each component’s contribution, we per-form a subtractive ablation study on the validation set using Mistral-24B (Table 3). Removing Task Decomposition drops macro-F1 from 0.65 to 0.59 , as single-pass queries suf-fer severe recall loss on multi-valued relations: 

awardWonBy collapses from 0.25 to 0.00 and 

countryLandBordersCountry falls from 0.98 to 

0.63 . Removing the Empty-Set Gate lowers macro-F1 to 0.57 due to hallucinated answers for unanswerable entities, severely hurting preci-sion on personHasCityOfDeath (0.50 → 0.36 )and companyTradesAtStockExchange (0.76 →

0.57 ). Finally, removing CoT Reasoning en-tirely causes the largest drop to 0.43 , heav-ily degrading hasArea (0.82 → 0.55 ) and 

countryLandBordersCountry (0.98 → 0.27 ), confirming that our gains stem primarily from structured parametric reasoning rather than output parsing alone. 

6 Discussion 

Relation-Aware Prompting versus Zero-Shot Prompting. In the zero-shot setting, all models exhibit limited and relatively similar performance. Requiring a model to recall facts and produce valid JSON in a single pass is especially difficult for re-lations with large object sets, such as awardWonBy ,and for quantitative relations that demand precise values, such as hasArea and hasCapacity . Ap-plying the complete two-stage pipeline of R EAP 

with relation-specific prompts, CoT reasoning, a reasoning-based empty-set gate, and direct parsing improves all three models. These results indicate that structured reasoning is important for reliably eliciting knowledge encoded in model parameters. 

Limits of Parametric Knowledge. Our results reveal a clear gap between the 9B model (Gemma-2-9B) and the 24B model (Mistral-24B). Run-to-run variance. Two minor sources of variation affect our runs. First, awardWonBy uses sampling ( T = 0 .7, six decade-scoped passes) to diversify recall over long recipient lists, so its score fluctuates slightly given only 10 validation awards. Second, even under greedy decoding ( T = 0 .0) the TPU v5e-8 is not bit-exact, because the accumula-tion order of bfloat16 values differs across its eight cores. Both effects are small—overall macro-F1 varies by about ±0.005 —and do not change our conclusions. 

7 Conclusion 

We presented the R EAP system for the AKBC Shared Task 2026 under a strict closed-book setting with at most 32B parameters, no exter-nal knowledge, and no model fine-tuning. The system implements a unified two-stage pipeline with Mistral-Small-24B-Instruct-2501, combining relation-aware prompt engineering, a reasoning-based empty-set gate, and direct parsing. It achieves a macro-F1 of 0.65 on the validation set and a macro-F1 of 0.62 on the official test set. The results demonstrate that structured reasoning can effectively elicit factual knowledge encoded in model parameters for knowledge base construction. 

Limitations 

Despite its promising performance, our system has several limitations: (i) its parametric knowledge remains incomplete for very rare, long-tail enti-ties; (ii) predictions for quantitative relations some-times fall outside the 5% relative-tolerance thresh-old because of retrieval or rounding errors; and (iii) stochastic sampling for awardWonBy , together with non-deterministic distributed computation on TPU v5e-8, causes slight variation across runs. Among the six relations, hasCapacity is the most chal-lenging (test macro-F1 0.23 ): venues are frequently confused with larger namesakes in the same city, and even small numeric errors exceed the 5% tol-erance.
