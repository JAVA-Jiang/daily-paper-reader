## 摘要
不断演化的文档，如法律、税法和软件文档，会随时间被修订、替换，有时甚至被回滚，因此同一个问题在不同日期有不同的正确答案。与百科全书式知识（旧事实被简单覆盖）不同，修正案本身是官方文本，它说明了替换的内容和生效时间，而早期版本在其有效期内仍然正确。因此，核心挑战在于版本解析，即识别查询日期时有效的版本。现有的时间问答数据集仅将时间视为注释，因此版本解析未得到测试。我们提出了TIDE，这是一个专家验证的基准测试，包含3050个问答对，涵盖孟加拉国政府于1969年至2025年间发布的644份官方海关文书，涉及八种任务类型，这些文档深度混合了代码，布局异构，并使用两种日历标注日期。此外，我们在统一协议下评估了九个最新的LLM，涵盖参数访问、黄金上下文检索和检索访问，并由一个三法官LLM委员会进行评分，该委员会设有严格的日期门控，以区分正确含义和正确时间。最佳的宏观平均准确率仅为68.5%。从隐含日期解析版本达到59.7%，而检测所提供的版本不适用于查询仅达到26.7%。模型更倾向于找到正确版本而非拒绝错误版本，并且它们倾向于遵循自信的参数答案而非提供的权威文本。所有代码和数据可在https://github.com/icsetepa44/TIDE获取。

## Abstract
Evolving documents, such as laws, tax codes, and software documentation, are amended, replaced, and sometimes reverted over time, so a question has different correct answers at different dates. In contrast to encyclopedic knowledge, where an old fact is simply overwritten, an amendment is itself an official text that states what it replaces and when it takes effect, and the earlier version stays correct for its validity period. The central challenge is therefore version resolution, that is, identifying the version in force on the queried date. Existing temporal QA datasets treat time only as an annotation, so version resolution stays untested. We present TIDE, an expert-verified benchmark of 3,050 QA pairs over 644 official customs instruments issued between 1969 and 2025 by the Government of Bangladesh, covering eight task types over deeply code-mixed documents that are heterogeneous in layout and dated in two calendars. In addition, we evaluate nine recent LLMs under a single protocol across parametric, gold-context, and retrieval access, scored by a three-judge LLM council with a hard date gate separating correct meaning from correct time. The best macro-averaged accuracy is only 68.5%. Resolving a version from an implicit date reaches 59.7%, and detecting that the supplied version does not govern the query reaches only 26.7%. Models are more likely to find correct versions than to reject incorrect ones, and they tend to follow a confident parametric answer over the supplied authoritative text. All code and data are available at https://github.com/icsetepa44/TIDE

## 1. 核心问题与整体含义

- **研究背景**：现有时间问答（Temporal QA）基准（如 TempReason、MenatQA、EvolveBench、evolveQA 等）大多只把“时间”当作事实的注解或扰动条件，并未真正建模一种关键场景：**演化文档（Evolving Documents）**——例如法律、税法、软件文档等，会随时间被正式修订、替换或回滚。
- **核心问题**：与维基百科式“旧事实被直接覆盖”不同，法律修正案本身是官方文本，会明确说明“替换了什么”和“何时生效”，旧版本在其有效期内仍然是正确答案。因此，回答关于此类文档的问题时，模型必须做**版本解析（Version Resolution）**：确定查询日期所对应的在有效版本。现有基准完全没有测试这一能力。
- **论文贡献**：提出 **TIDE（Temporal Information Drift in Evolving Documents）** 基准，基于 1969–2025 年孟加拉国政府发布的 644 份官方海关文书，构建 3,050 个 QA 对，覆盖 8 种任务类型；并对 9 个主流 LLM 在参数记忆、黄金上下文、检索增强三种设置下进行系统评测，揭示版本解析仍是远未解决的问题。

## 2. 方法论

- **总体流程**：数据采集 → 文档解析 → 实体/概念提取 → 实体聚类与演化线程构建 → 时间问答对生成 → 专家验证 → 多设置评测。

#### 2.1 数据来源与解析

- 从孟加拉国国家税务局官网收集 644 份 PDF：3 部法案、20 项 General Orders、609 项 SROs、12 项 Rules，时间跨度 1969–2025。
- 文档高度异构：包含孟加拉语–英语深度代码混合文本、内嵌关税表格、双历法日期（孟加拉历和公历）、非统一版面等。
- 使用 Gemini 3.1 Pro 按自定义的 JSON schema 抽取条款、子条款层级、表格和元数据；13 名志愿者人工校验 OCR 忠实度，词错误率仅约 0.07–0.08%。

#### 2.2 实体、概念与演化线程

- **实体–概念抽取**：利用 Gemini 3.1 Pro 从每一条款提取规范化的官方英文实体名和自然语言概念描述，并按文档层级（Act/SRO/Rule/GO）控制概念粒度。
- **实体聚类**：对表面形式做嵌入表示，保留余弦相似度 ≥0.90 的近邻，再用贪心集合覆盖打包成“判断单元”，由别名判定模型（Gali）确认真正的别名/缩写/数字变体，并通过 union-find 生成最终实体簇。
- **演化线程（Thread）**：只有跨至少两个日期的实体簇才进入后续流程；按日期排序生成“监管主题时间线”，记录每个版本设定的值、变更维度（法律依据、税率、资格、范围等），并剔除重复的官方套话。

#### 2.3 时间问答对生成

- 生成器 Ggen 以线程为唯一输入，按 8 种任务类型分别生成，保证答案在生成时就具备时间正确性和条款可追溯性（每个问答对都引用具体 clause ID 和源文件）。
- 两位领域专家独立验证，94.89% 的问答对被评为“完全正确”，Cohen's κ = 0.91，专家会现场修正或重写低分项。

#### 2.4 八种任务类型

1. **Temporal MCQ**：时间选择题，干扰项在编号/日期上高度相似，考查纯版本解析能力。
2. **Event Sorting**：把无日期、乱序的事件按时间先后排列，必须通过“每次变更做了什么”推断顺序。
3. **Perturbation Detection**：判断一段陈述是否被篡改，并定位/更正被篡改的事实。
4. **Scenario Short Answer**：在单文件、单一版本情境中抽取税率等数值，作为单版本基线。
5. **Temporal Scenario Short Answer**：给定查询日期，在多个相互修订的文件中找出当时有效版本，是修正语义的最直接测试。
6. **Relative-Time QA**：给出锚定时间和偏移（如“三年后”），先计算目标日期再取值，分离时间算术与内容查找。
7. **Open-Ended**：回答“为什么/怎么样”演变的开放性问题，检验是否真正理解变化方向/动因。
8. **Context Misalignment**：给出一段自信但错误的误导性上下文，考查模型能否不跟随错误前提，坚持权威事实。

#### 2.5 评测协议

- **三种知识访问设置**：
  - 参数知识（Parametric）：闭卷，完全依赖模型内部记忆。
  - 黄金上下文（ICL）：在提示中给出构建该问题所用的原始文档。
  - RAG：用 gemini-embedding-2 嵌入语料（6,939 个向量），按余弦相似度取 top-40，再映射为至多 10 个完整父条款。
- **LLM 评委会（LLM Council）**：三个异质模型（Claude Opus 4.6、Gemini 3.5 Flash、GPT-5.1）各自输出固定的是/否 JSON 向量，程序取多数票后按公式评分。
- **评分公式（硬日期门控）**：
  ```
  S(m,n,μ) =
    [μ]                       if n=0
    0.5 + 0.5·[μ]             if n=1, m=1
    0                         if n=1, m=0
    0.5·(m/n) + 0.5·[m=n∧μ]   if n≥2
  ```
  其中 n 是标准答案中的规范日期数，m 是模型答案满足的日期数，μ 是含义正确与否的布尔值。**日期错误直接记 0 分**，即使含义正确也不能得分。
- 评委会间 Fleiss' κ ∈ [0.8297, 0.861]，两位外部专家对评委会的再评分一致率约 94.21%。

## 6. 主要结论与发现

- **总体表现很低**：最优宏平均严格准确率仅 **68.49%（GPT-5, ICL）**；版本敏感任务大幅低于该水平。
- **知识获取顺序稳定**：所有模型均呈现 Parametric < RAG < ICL，说明“能否读到文本”比“模型身份”更决定成绩；但即使提供黄金文档，仍远未解决版本解析。

- **发现正确版本 ≠ 拒绝错误版本**：Context Misalignment 是最难任务，ICL 下最高仅 27.62%；模型倾向于跟随“自信但错误的前提”，即使正确条款就在同一提示中。

- **参数记忆的两面性（续）**：模型在闭卷时能记住“存在某个文件/法规”，却无法解析“哪个版本在指定日期有效”，说明参数化记忆捕获的是概念性存在而非版本化语义；一旦问题要求精确到“某一天适用哪一条”，闭卷成绩迅速崩塌，且所有模型均未表现出例外。

- **有意义的次要发现**：
  - 表现最好的模型在单版本基线（Scenario SA）上均超过 90%，说明基础信息抽取能力已基本成熟；瓶颈完全集中在时间解析层。
  - 相对时间问答（Relative-Time QA）的得分普遍低于绝对时间问答，说明“先算日期再查值”这一组合推理仍未被现成模型掌握。
  - 消融显示，检索深度从 Top-5 提升到 Top-15 带来的收益有限（平均约 3–5%），说明问题不在于“检索到多少”，而在于“检索器对时间条件的排序天然不敏感”。

## 7. 局限性与批评

- **领域与语言单一性**：TIDE 只基于孟加拉国海关文书（孟加拉语–英语深度代码混合、孟加拉历与公历双日历），在法律、税法、软件文档等其他演化文档上的可迁移性尚未被验证。作者承认这是“版本解析的最难形态之一”，但也意味着基准可能过度适配该领域的文本形态。
- **数据构建依赖单一模型**：条款解析、实体抽取、演化线程构建及问答对生成全部依赖 Gemini 3.1 Pro，虽有 13 名志愿者的 OCR 校验和两位 SME 的问答对审核，但上游抽取的潜在系统性偏差会向下游传播，无法完全排除。
- **无法验证数据污染**：闭卷参数记忆实验建立在“模型预训练语料包含这些政府文书”的假设上，但论文未做数据污染检测，也未公开用于污染筛查的文档时间戳匹配方法；因此 Parametric 分数偏低既可能是模型能力不足，也可能是语料根本不在预训练数据中。
- **RAG 仅代表性能下限**：检索器为零样本语义嵌入、无时间元数据注入、无重排序；作者明确将 RAG 设定解释为“下限”而非“代表真实检索系统”，这使得 RAG 与 ICL 之间的差距更像“检索完备性差距”而非“推理差距”。
- **未探索训练侧干预**：全部评测均为零样本推理，没有实验覆盖继续预训练、指令微调、时间感知检索、思维链提示等可能的缓解路径，因而“版本解析不可解决”的结论只能局限于当前 API 模型范畴。
- **评分门控极端**：硬日期门控（日期不符直接记 0 分）虽保证了严格性，但也惩罚了“含义正确、日期格式误写”的答案，可能低估模型在有容错评分下的真实能力。
- **规模有限**：3,050 个 QA 对覆盖 157 个主题簇、265 条线程，作为基准仍属中规模，更细粒度的版本链（如一个主题经历 10 次以上修订）样本不足，难以支撑长时序推理的结论。

## 8. 总体评价与启发

- **核心贡献是任务定义而非模型**：TIDE 最重要的价值在于将“版本解析”从事实问答中分离出来，并给出可计算、可审核的构造方法（线程 → 版本序列 → 时间门控 QA）。这为后续时间问答研究提供了新的评测维度。
- **“检测 ≠ 识别、发现 ≠ 拒绝”具有跨任务普适性**：模型能在扰动检测中判断“有篡改”，却无法指出被篡改的具体内容；能在上下文中看到正确版本，却仍跟随错误前提。这两个结论不是琐碎的失败模式，而是对当前模型“表面服从、内部不一致”的清晰量化。
- **硬日期门控值得借鉴**：在评测中强制要求“日期与事实同时正确”能有效防止模型用泛泛正确内容蒙混过关，这一设计可直接迁移到法律、医疗、金融等领域的时间敏感 QA 评测。
- **对 RAG 系统的警示**：TIDE 证明语义检索在时间演化文档上存在系统性缺陷——检索器无法感知“不同日期对应不同版本”，即便相关条款被检索到，也可能因为排序靠后而被截断丢失。未来时间感知重排序、元数据过滤或日期条件检索应成为 RAG 的新研究重点。
- **对 LLM 能力的判断需谨慎**：在 ICL（黄金上下文）下最优仅 68.49%，说明即使所有事实都在眼前，模型依然无法稳定完成版本解析。这排除了“检索失败”这一解释，表明问题在于推理层——这也意味着仅靠扩大上下文或增加检索文档数不会解决，需要显式的时间推理机制。
- **建议引用时注意命名混淆**：“TIDE”在已有文献中可能指其他时间信息抽取或评测任务，建议作者考虑更独特的标识或补充全称（Temporal Information Drift in Evolving Documents），以减少检索歧义。

总体而言，TIDE 是一个设计严谨、评估透明、结论鲜明的时间问答基准。它的主要局限是领域单一性和零训练干预，但其核心贡献——版本解析任务的识别、构造方法与严格评分机制——足以使其成为时间问答乃至 RAG 评测的重要参考。
