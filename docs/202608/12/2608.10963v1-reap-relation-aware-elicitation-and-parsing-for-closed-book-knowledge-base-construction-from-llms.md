## 摘要
我们提出了用于AKBC共享任务2026的REAP系统，该任务在封闭书设置下从语言模型中构建知识库，参数预算不超过32B，且不允许模型微调。我们的系统结合了结构化思维链推理、关系特定查询策略以及基于推理的空集门来激发参数化知识，然后直接提取为有效的JSON数组。在测试集上，该系统基于Mistral-Small-24B-Instruct-2501模型构建，取得了0.62的宏F1分数，在countryLandBordersCountry（F1 = 0.95）、companyTradesAtStockExchange（F1 = 0.73）和hasArea（F1 = 0.77）关系上表现尤为突出。我们的代码公开可用，地址为https://github.com/yammdd/AKBC-Shared-Task-2026。

## Abstract
We present the REAP system for the AKBC Shared Task 2026 on constructing knowledge bases from language models in a closed-book setting, subject to a budget of at most 32B parameters and no model fine-tuning. Our system combines structured chain-of-thought reasoning, relation-specific query strategies, and a reasoning-based empty-set gate to elicit parametric knowledge, followed by direct extraction into valid JSON arrays. On the test set, the system, built on the Mistral-Small-24B-Instruct-2501 model, achieves a macro-F1 score of 0.62, with particularly strong results on countryLandBordersCountry (F1 = 0.95), companyTradesAtStockExchange (F1 = 0.73), and hasArea (F1 = 0.77). Our code is publicly available at https://github.com/yammdd/AKBC-Shared-Task-2026.

## 1. 论文的核心问题与整体含义

- **背景**：大语言模型（LLM）的参数中编码了大量事实知识，但要从模型中“抽取知识”并构建知识库（Knowledge Base Construction, KBC）比回答单个事实性问题更困难。一个 `(subject, relation)` 对应的答案可能为空集、单值或多值，而多数传统探针方法假设每个关系只有一个答案。
- **任务约束**：AKBC Shared Task 2026 要求系统在 **closed-book** 环境下运行，即不能使用检索增强生成或外部知识；模型参数量不超过 **32B**；且不允许对模型进行微调。
- **REAP 要解决的问题**：如何在严格受限、无外部知识、无微调的条件下，可靠地激发 LLM 的参数量化知识，并生成符合 JSON 格式、支持 0/1/N 基数的完整答案集合。
- **整体含义**：REAP 证明，在无法微调与检索的约束下，通过**结构化提示设计 + 思维链推理 + 关系特定查询策略**，仍然可以从模型中构建可用的知识库，为闭卷式 LLM 知识抽取提供了一种高效且实用的方案。

## 2. 论文提出的方法论

- **核心思想**：将“事实回忆”与“答案序列化”两个步骤解耦，采用两阶段流水线：
  1. **Stage 1**：用 LLM 生成证据或进行思维链（Chain-of-Thought, CoT）推理；
  2. **Stage 2**：从生成结果中用确定性解析或 LLM 抽取器得到合法 JSON 数组。
- **关系感知提示设计**：针对六类关系设计专用提示，核心原则包括：
  - **查询分解**：多值关系通过分解查询提高召回率；
  - **格式约束**：要求模型输出 `BORDERS:` 或 `FINAL_ANSWER: [...]` 等标记；
  - **空集门控**：对于不存在或信息不足的情况，模型应返回 `FINAL_ANSWER: []`。
- **各关系的专用策略**：
  - **awardWonBy**：按时间分段的多次查询，包括 1 个通用提示 + 5 个辅助提示（按年代划分），采样温度 T=0.7 以提高召回；
  - **countryLandBordersCountry**：四方向地理扫描（东、西、南、北），排除海上边界，岛国返回空集；
  - **companyTradesAtStockExchange**：四步 CoT，先判断公司是否为私有/非营利/非独立上市子公司，再列出交易所官方名称；
  - **hasArea**：四步 CoT，进行实体消歧、参数回忆、单位转为 km²、输出数值；
  - **hasCapacity**：四步 CoT，包含场地类型判断、同名校名消歧、容量范围校验（小场馆 1000–35000；大型国家体育场 35000–100000）；
  - **personHasCityOfDeath**：五步 CoT，包括存活判断、姓名消歧、死亡地点回忆、城市名提取、空集判断。
- **后处理与解析**：
  - 直接解析 `FINAL_ANSWER:` 行；
  - 对截断 JSON 使用括号配对扫描恢复；
  - 对数值型关系进行单位、千位分隔符清洗；
  - 对奖项实体去除年份前缀、头衔、HTML 标签；
  - 去除括号限定词并做大小写不敏感去重。
- **混合解析效率**：约 80% 的记录可由确定性解析完成，LLM 抽取器只作为复杂输出时的 fallback，从而降低计算成本。

## 3. 实验设计

- **数据集 / Benchmark**：
  - AKBC Shared Task 2026 数据，包含 6 个关系；
  - validation 和 test 各 475 条记录；
  - 具体分布：`countryLandBordersCountry` 验证集 68 条/测试集 67 条；`hasCapacity` 97/98；`awardWonBy` 10/10；其余关系各 100/100。
- **评估方式**：
  - 使用官方 `evaluate.py`，报告 macro/micro precision、recall、F1；
  - 字符串关系通过别名和最大二分匹配进行对齐；
  - 数值关系使用 5% 相对误差容限。
- **对比方法**：
  - 组织者基线：Qwen3.5-9B；
  - 其他模型：Gemma-2-9B-it、Llama-3.1-8B-Instruct；
  - 主模型：Mistral-Small-24B-Instruct-2501；
  - 对比条件包括 **zero-shot 直接查询** 与 **完整 REAP 两阶段流水线**。
- **实验结果**：
  - 零样本设置下，三个模型 macro-F1 仅为 0.38–0.43；
  - 应用 REAP 后：Llama-3.1-8B 从 0.38 提升到 0.48，Gemma-2-9B 从 0.42 提升到 0.51，Mistral-24B 从 0.43 提升到 0.65；
  - 官方测试集上，REAP + Mistral-24B 总体 macro-F1 为 **0.62**，显著高于 Llama/Gemma 管线的 0.48 和组织者基线 Qwen3.5-9B 的 0.30；
  - 关系级测试结果：`countryLandBordersCountry` 0.95、`hasArea` 0.77、`companyTradesAtStockExchange` 0.73、`personHasCityOfDeath` 0.53、`awardWonBy` 0.37、`hasCapacity` 0.23。
- **消融实验**：
  - 去掉任务分解（Task Decomposition）：macro-F1 从 0.65 降至 0.59；
  - 去掉空集门（Empty-Set Gate）：降至 0.57；
  - 去掉思维链（CoT）：降至 0.43，说明 CoT 是最关键组件。

## 4. 资源与算力

- **未使用 GPU**，而是在 **Kaggle** 上使用 **TPU v5e-8**，共 8 个 TPU v5e core。
- 使用 **vLLM TPU Server** 进行模型服务，精度为 **bfloat16**，`batch_size=32`。
- 在 validation 上完整运行 475 条记录约需 **2–5 分钟**。
- 由于系统不进行微调，资源主要用于推理；论文没有报告训练耗时或更细粒度的分关系推理成本。

## 6. 论文的主要结论与发现

- **零样本直接提问效果有限**：所有模型在 zero-shot 下表现相近且较差，说明“回忆事实 + 满足输出格式”单步完成非常困难。
- **结构化推理显著有效**：完整 REAP 流水线能够大幅提升所有模型的 macro-F1，尤其对多值关系和数值型关系帮助最大。
- **学习到的知识依赖于模型容量**：24B 的 Mistral 在完整流水线下明显优于 9B 模型；提示推理能减少格式噪声，但事实回忆能力仍取决于参数规模。
- **空集门控很关键**：能有效抑制对不存在答案的幻觉，显著提高 precision，尤其影响 `personHasCityOfDeath` 和 `companyTradesAtStockExchange`。
- **闭卷构建知识库具有可行性**：在 32B 参数、无微调、无检索的限制下，通过关系感知提示和结构化解析，依然能在多种关系上取得可用性能。
- **任务难点明确**：`hasCapacity` 是最大的难点，场馆容量容易与同名或同城市的大型场地混淆，数值误差经常超过 5% 容限；长尾实体是闭卷设定下的固有瓶颈。

## 7. 优点

- **方法实用且系统化**：把知识抽取拆分为“回忆”和“解析”两阶段，模块清晰，便于扩展。
- **关系级别提示设计细致**：针对每种关系的语义特点设计不同查询策略，例如奖项按年代多遍查询、国土边界按方向扫描，有效提升召回。
- **空集门控机制有效**：减少了模型对不存在事实的臆测，提升了 precision。
- **解析效率高**：确定性解析覆盖约 80% 记录，降低推理成本。
- **遵守任务限制**：不微调、无外部知识、不使用超过 32B 的模型，且 few-shot 示例不泄露评估数据。
- **消融实验完整**：能够清晰分离各组件贡献，尤其是确认 CoT 的重要性。
- **代码开源**，便于复现和后续改进。

## 8. 不足与局限

- **长尾实体效果有限**：模型对罕见、冷门实体的参数化知识不完整，导致 recall 受限。
- **数值型关系精度不够**：`hasArea` 和 `hasCapacity` 的细小回忆或单位转换错误都可能超过 5% 容限，其中 `hasCapacity` 测试 F1 仅 0.23。
- **奖项类多值关系不稳定**：`awardWonBy` 使用采样生成多条结果，且验证集只有 10 条记录，结果波动较大。
- **TPU 并行计算存在非确定性**：即使 greedy decoding，bfloat16 的累加顺序在多核间不完全一致，导致轻微的 run-to-run 差异。
- **实验覆盖有限**：只覆盖 6 个关系，且测试集规模较小；没有对分布外实体或跨领域关系进行测试。
- **存在验证集调优风险**：关系提示、few-shot 示例和解析规则可能针对验证集进行过调整，泛化能力需要在更广数据上进一步验证。
- **缺少更强基线对比**：除了组织者基线外，没有与更多近年 LM-KBC 竞赛系统（如 ReWiSe 等）进行直接实验对比。
