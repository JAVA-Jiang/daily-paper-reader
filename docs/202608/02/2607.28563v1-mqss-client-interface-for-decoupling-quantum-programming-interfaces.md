## 摘要
量子计算（QC）是一种新兴技术，需要定制化的工具，如软件栈和编程接口。然而，目前这些工具通常是紧密耦合的，互操作性有限。这尤其影响到高性能计算（HPC）设施和数据中心，因为它们需要支持多种编程接口。在本文中，我们介绍了MQSS客户端，这是一个统一的、上下文感知的访问层和编程库，它将编程接口与底层编译和运行时栈解耦。MQSS客户端旨在通过提供资源、作业和结果的抽象来支持所有现有的编程接口。它提供了两种访问模式，以适应远程和HPC用户的不同需求。因此，软件栈和编程接口之间的互操作性得以提高。

## Abstract
Quantum Computing (QC) is an emerging technology that requires customized tools, such as software stacks and programming interfaces. However, currently, the tools are generally tightly coupled and exhibit limited interoperability. This, in particular, affects High Performance Computing (HPC) facilities and data centers, which are required to support multiple programming interfaces. In this paper, we introduce MQSS Client, a unifying, context-aware access layer and programming library that decouples the programming interfaces and the underlying compilation and runtime stack. MQSS Client aims to support all existing programming interfaces by providing abstractions for resources, jobs, and results. It provides two access modes to accommodate the varied needs of remote and HPC users. Thus, interoperability between software stacks and programming interfaces increases.

## 2. 方法论

### 核心思想
- 设计并实现 **MQSS Client**——一个统一的访问层和编程库，位于"编程接口/最终用户"与"底层编译/运行时栈"之间。
- 通过抽象三大核心领域对象（资源、作业、结果），屏蔽底层后端的异构性，实现"一次开发、多后端适配"。

### 关键技术细节
- **统一入口**：`MQSSClient`类作为所有用户交互的唯一入口，对外暴露一致的API。
- **两种访问模式**（均实现统一的`MQSSBaseClient`接口）：
  - **REST远程/云访问**（`MQSSRestClient`）：基于HTTP端点，使用libcurl实现通信。
  - **RabbitMQ的HPC访问**（`MQSSHPCClient`）：面向高性能数据中心，使用rabbitmq-c实现消息传递。
- **作业抽象**：支持两种作业请求类型——
  - `CircuitJobRequest`：门级电路程序（如OpenQASM 2.0）描述，包含shots数等参数；
  - `HamiltonianJobRequest`：哈密顿量能谱计算任务，包含相互作用项和系数。
- **资源抽象**（`Resource`）：动态提供耦合映射、量子比特数、原生门集、在线状态等能力查询。
- **部署形态**：既可作为**独立客户端库**（C++/Python）使用，也可嵌入为**后端适配器**，对接Qiskit、PennyLane、CUDA Quantum、QPI、QDMI等多种编程框架。
- **实现语言**：C++17核心（利于HPC性能），通过pybind11生成Python绑定。
- **结果获取**：`getJobResult`支持阻塞/非阻塞模式，返回结果直方图及提交/调度/完成时间等元数据。
- 论文未涉及具体数学公式或算法流程，重点在软件框架的设计与实现。

## 6. 主要结论与发现

- **MQSS Client的操作开销可忽略**：与直接实现相比，总执行时间差异~9%（C++/HPC），部分场景Python客户端甚至快于Python直接实现。
- **C++核心优于纯Python**：说明以C++为底层核心、以Python封装上层是有益的架构选择。
- **Python绑定的性能开销极小**，足以支撑常用量子开发工作流。
- **HPC访问模式在作业提交和资源查询上显著优于远程模式**，远程模式的延迟主要来自网络通信（如资源查询约200–300 ms vs. HPC约6–25 ms）。
- **量子电路执行时间（EQC）占总执行时间约84.5%**，客户端层的开销占比微乎其微。
- 客户端已成功支撑多个编程接口与框架的适配（Qiskit、PennyLane、CUDA Quantum、QPI、QDMI、基准框架），证明了解耦设计的实际可行性。

## 7. 优点

- **清晰的解耦架构**：通过`MQSSBaseClient`接口将传输逻辑内部化，对外API保持一致，设计整洁。
- **双层抽象**：作业（电路/哈密顿量）+ 资源查询模型设计合理，覆盖了典型量子应用场景。
- **多语言、多框架支持**：通过绑定和适配器设计，同时服务于C++和Python生态，并能无缝对接Qiskit、PennyLane、CUDA Quantum等主流SDK，工程实践价值高。

- **对HPC场景的深度适配**：RabbitMQ通道满足低延迟、高吞吐的HPC消息需求；同时兼顾远程轻量用户。
