## 摘要
自主编码智能体如今开启了数百万个拉取请求，然而大规模研究发现，它们的PR生成速度更快，但接受率却更低——这是拉取请求级遥测无法解释的协作与信任差距。我们认为缺失的信号存在于PR之前，体现在并发智能体如何认领、划分和冲突处理共享工作。我们通过开源协作基础平台grite来研究这一过程，该平台无需中央服务器，并将记录直接存储在git内部，因此其追加写入、签名的日志可直接捕获协作过程。我们证明：(i) 这一共享基础平台以可接受的开销减少了重复和冲突工作——仅重复团队成员任务的工作占比从78%降至0%，而有用的吞吐量增加了三倍以上；(ii) 每个智能体的日志副本收敛到相同状态，没有写入被静默丢弃，而基于文件的跟踪器会丢失并发写入；(iii) 日志是一种可挖掘的产物，从中可自动恢复具体的失败模式——冲突编辑、锁饥饿、冗余重新发现、争相关闭——并带有溯源信息，其中几种在拉取请求历史中不可见。我们发布了数据集、测试平台和挖掘工具包。

## Abstract
Autonomous coding agents now open millions of pull requests, yet large-scale studies find their PRs are produced faster but accepted less often - a coordination and trust gap that pull-request-level telemetry cannot explain. We argue the missing signal lives before the PR, in how concurrent agents claim, divide, and collide over shared work. We study this process through grite, our open-source coordination substrate that needs no central server and stores its records inside git itself, so its append-only, signed event log captures the coordination process directly. We show that (i) this shared substrate reduces duplicate and conflicting work at bounded overhead - the share of work that merely re-does a teammate's task falls from 78% to 0% while useful throughput more than triples; (ii) every agent's copy of the log converges to the same state with no write silently dropped, where a file-based tracker loses concurrent writes; and (iii) the log is a mineable artefact from which concrete failure modes - conflicting edits, lock starvation, redundant rediscovery, race-to-close - are automatically recoverable with provenance, several invisible in pull-request history. We release the dataset, harness, and mining toolkit.

### 1. 论文的核心问题与整体含义（研究动机和背景）
- **研究动机**：自主编码智能体（如Codex、Devin、Copilot等）正在大规模生成拉取请求（PR），但研究发现它们生成的PR速度更快，接受率却更低。现有的大规模分析（如AIDev数据集）只能看到PR级别的结果（合并或拒绝），而**无法捕获PR之前的协作过程**——即并发智能体如何认领、划分和冲突处理共享工作。这种“协作与信任差距”是PR级遥测无法解释的。
- **整体含义**：论文主张，要理解PR接受率低的原因，需要研究PR之前的协调过程。作者开发了开源工具`grite`，将协调事件日志嵌入git，无需中央服务器，使协调过程可测量、可挖掘。通过实验证明，共享协调基板能大幅减少重复和冲突工作，且日志本身可作为可挖掘的软件工程产物，恢复PR历史中不可见的失败模式。

### 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：将智能体协调过程视为一个**可记录的、无服务器的、基于git的事件日志**，通过冲突自由复制数据类型（CRDT）保证日志收敛，并用咨询锁提供互斥。
- **关键技术细节**：
  - **grite系统**：基于git的协调基板，无中央服务器。所有协调动作（创建、更新、评论等）作为**追加写入、内容可寻址、可选签名的事件**存储在git引用（`refs/grite/wal`）中，随代码通过普通`fetch`/`push`传播。
  - **CRDT投影**：从事件日志重建问题的物化状态。标量字段使用最后写入者获胜（LWW），集合字段（标签、指派人等）使用可交换合并，保证不同副本按任意顺序接收相同事件后得到字节完全一致的状态。
  - **咨询锁**：通过`refs/grite/locks`中的TTL绑定租约实现互斥。智能体在开始工作前获取租约，工作期间续期，完成后释放。租约是建议性的（advisory），可被忽略，这本身也是可测量行为。
  - **依赖图与同步**：问题间可建立有向边（阻塞、依赖等），支持循环检测。同步只需拉取/推送grite引用并执行CRDT合并，无需中央服务器或共识协议。
- **流程示例**：智能体循环：选择候选任务 → 在锁机制下尝试获取租约（若被拒则退避） → 通过grite发出真实事件（选择、更新、关闭） → 仪器化的CRDT投影记录冲突和重复标志。

### 3. 实验设计：使用了哪些数据集 / 场景，它的 benchmark 是什么，对比了哪些方法
- **数据集/场景**：使用**合成代理（tier-T1）**，而非真实LLM代理。任务池是一组抽象的独立工作单元，部分任务重叠以产生竞争。固定池大小，改变并发代理数N ∈ {2, 4, 8, 16, 32}。所有结果基于随机种子多次运行的平均值。
- **Benchmark**：没有外部标准benchmark。论文设计了三种对比臂（协调臂）：
  - **no-coord**（无协调）：代理自由选任务，无任何协调机制（默认状态）。
  - **locks-only**（仅锁）：代理在工作前获取咨询锁，防止同时处理同一任务，但无已完成任务的共享记录。
  - **locks+state**（锁+共享状态）：代理既使用锁，又查询共享任务状态，跳过已完成任务。
- **对比方法**：除协调臂之间的对比外，还对比了一个**基于文件（JSONL）的基线**：使用文件级最后写入者获胜来协调状态，以展示grite的CRDT优势。

### 6. 论文的主要结论与发现
- **C1（协调效率）**：无协调时78%的工作是重复的；仅使用锁将冲突编辑从410降至138，但重复率仍有64%；锁+共享状态使重复率降至0%，吞吐量从2.33提升至8.00（N=32）。效果单调：无协调下重复率随N上升，而锁+状态始终为零。
- **C2（收敛无丢失）**：grite的CRDT保证两个副本在收到相同事件后（无论顺序）产生字节完全一致的状态，且重放幂等；而文件级LWW基线会静默丢失并发写入（如一个智能体设置的标签被另一个覆盖）。
- **C3（日志可挖掘性）**：从协调日志可自动检测具体故障模式，如冲突编辑、冗余重新发现、锁饥饿等。其中几种模式在PR历史中不可见（如被拒绝的锁请求不会成为提交）。特别发现：仅使用锁并不能解决冗余重新发现（锁不会阻止重新做已完成任务），只有锁+共享状态才能将其降至零。
- **核心设计教训**：**互斥与冲突自由共享状态是联合必要的**，缺一不可。

### 7. 优点：方法或实验设计上的亮点
- **创新性**：首次将PR之前的协调过程作为可挖掘的软件工程产物，提出无服务器的git原生协调基板，填补了现有PR级研究的空白。
- **设计巧妙**：利用CRDT和git refs实现离线优先、无需中央服务器的协调，降低了部署复杂性。
- **可复现性**：所有结果可一键再生（`make figures`），种子、提交、版本均固定，符合开放科学原则。
- **实验控制干净**：使用合成代理避免LLM的随机性和代码质量混淆，使因果归因清晰。
- **测量机制集成**：冲突和重复标志由系统内部计算，而非外部模型，减少了测量误差。
- **提供完整开源工具**：grite系统、数据集、测试平台和挖掘工具包均公开，便于其他研究者复现和扩展。

### 8. 不足与局限：包括实验覆盖、偏差风险、应用限制
- **外部有效性**：最大局限——智能体是**合成op生成器**，在抽象任务池上运行，而非真实LLM代理在真实代码库上工作。因此绝对数值（如78%重复率）可能无法直接推广到真实场景。作者承认这一点，并计划未来收集tier-T2（LLM代理）日志。
