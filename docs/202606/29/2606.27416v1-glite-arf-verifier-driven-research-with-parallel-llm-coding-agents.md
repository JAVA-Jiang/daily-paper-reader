## 摘要
LLM编码代理使得通过直接委托实验来自动化实证研究变得诱人，但简单的委托无法扩展到大型项目：低率的指令错误会累积成破碎、不可复现的人工制品。为了解决这个问题，我们提出了Glite ARF，这是一个开源的Python框架，用于在研究代码库上并行运行多个LLM编码代理，同时不牺牲可复现性或可审计性。该框架定义了一个三角色堆栈：人类研究人员选择要测试的假设，编码代理（Claude Code、Codex CLI）在固定结构下实现单个任务，而确定性的Python验证器脚本强制执行任务隔离、已完成工作的不可变性、修正覆盖层以及物化的项目概览。我们称之为验证器驱动的研究：研究过程的规则存在于代码中，违反时会大声失败，而不是存在于仅仅要求代理遵循的散文中。使用Glite ARF，我们开发了提交给BEA 2026词汇难度共享任务的作品，在所有三种目标语言（西班牙语、德语、普通话）的封闭赛道中排名第一，开放赛道中排名第二，并将官方基线RMSE降低了29.9%（封闭）和35.9%（开放）。这次活动包括273个跟踪任务（146次实验运行），涵盖129个特征集，由最多12个并行代理从一台笔记本电脑上协调运行——部分模型训练在租用的A100上进行——LLM API花费约450美元（第三方总成本498美元），并且结构化的每折溯源使我们能够捕获并剔除了四个目标泄露的特征集，将不切实际的0.609 RMSE修正为0.802。在三个领域的三个活动中，该框架的结构性开销仅增加约1%的挂钟时间。本文附带了框架和一个公开演示项目。

## Abstract
LLM coding agents make it tempting to automate empirical research by delegating experiments to them directly, but naive delegation does not scale to large projects: low-rate instruction lapses compound into broken, irreproducible artefacts. To address this problem, we present Glite ARF, an open-source Python framework for running many LLM coding agents in parallel on a research repository without sacrificing reproducibility or auditability. The framework defines a three-role stack: a human researcher chooses which hypotheses to test, coding agents (Claude Code, Codex CLI) implement individual tasks under a fixed structure, and deterministic Python verifier scripts enforce task isolation, immutability of completed work, a corrections overlay, and a materialised project overview. We call this verifier-driven research: the rules of the research process live in code that fails loudly when violated, not in prose that agents are merely asked to follow. Using Glite ARF, we developed our submission to the BEA 2026 vocabulary-difficulty shared task, placing first in the closed track and second in the open track on all three target languages (Spanish, German, Mandarin) and reducing the official baseline RMSE by 29.9% (closed) and 35.9% (open). The campaign comprised 273 tracked tasks (146 experiment runs) across 129 feature sets, run by up to twelve parallel agents orchestrated from a single laptop - with some model training on rented A100s - at approximately \$450 in LLM API spend (\$498 total third-party cost), and structured per-fold provenance let us catch and strip four target-leaking feature sets, correcting an implausible 0.609 RMSE to 0.802. Across three campaigns in three domains, the framework's structural machinery adds only about 1% of wall-clock time. Framework and a public demo project accompany this paper.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：使用 LLM 编码代理直接执行实验虽然诱人，但轻微的指令偏差（如漏执行、错误修改文件）会在大规模多代理并行中累积，导致人工制品不可复现、不可审计（如数据污染、目标泄露、手工统计错误）。
- **根源**：现有方法依赖“在提示中写入规则”，但低出错率（约 1–5%）在多周、数百次任务中也会累积为大量错误。
- **目标**：提出一个结构化的框架，使研究过程本身可执行、可验证，让规则以确定性代码而非自然语言形式存在，从而在不牺牲可复现性的前提下实现大规模并行 LLM 代理研究。
- **含义**：将“验证器驱动研究”类比测试驱动开发（TDD），将研究过程的约束转化为脚本，违反时立即失败，保证结构正确性。

## 2. 方法论：核心思想、关键技术细节
- **三角色堆栈**：
  - **人类研究者** (Role 1)：选择要测试的假设（建议级别）。
  - **编码代理** (Role 2)：在固定结构下实现单个任务（如 Claude Code、Codex CLI）。
  - **确定性 Python 验证器脚本** (Role 3)：强制执行任务隔离、已完成工作的不可变性、修正覆盖层、物化的项目概览。
- **七个结构原则**：
  1. **任务隔离**：每个任务位于独立文件夹和 git worktree，仅允许修改自身文件夹 + 少量共享配置文件；预合并验证器拒绝修改外部文件的提交。
  2. **不可变性 + 修正覆盖层**：已完成的任务文件夹不可修改；发现错误时，下游任务在自身文件夹写修正文件，聚合器在读取时叠加修正，保持原始记录完整。
  3. **仅通过聚合器在读时访问其他任务**：禁止直接遍历任务文件夹；所有跨任务视图由聚合脚本生成，避免手工统计错误（如“已完成任务 75 of 64”）。
  4. **物化项目概览**：`arf/scripts/overview/materialize.py` 生成静态、可浏览的 `overview/` 目录，作为唯一的人类可读摘要。
  5. **规范验证的工件**：每个工件（任务文件夹、结果文件、日志等）有版本化规范（specification），对应验证器在提交前检查格式、字段、版本匹配。
  6. **全面日志**：每个 CLI 调用通过 `run_with_logs.py` 记录命令、输出、退出码、时间戳；验证器要求日志存在才能标记步骤完成。
  7. **子代理隔离**：复杂任务分解为多个子代理（研究、规划、实现、分析、报告），每个独立上下文，避免长上下文退化。
- **任务生命周期**：9 步（论文阅读 → 搜索 → 代码阅读 → 计划 → 实现 → 分析 → 文献对比 → 报告 → PR 合并），每步可由不同子代理执行。
- **并行机制**：每个任务一个独立 git worktree 和分支，研究者为每个任务打开一个代理会话；验证器控制合并准入，避免冲突。

## 8. 不足与局限
- **人类持续在环路中**：角色 1（假设选择）仍由人类驱动，框架不自动生成或选择研究方向；作者明确认为这是有意设计，而非临时方案。
- **不捕获语义错误**：验证器只检查结构完整性（文件存在、格式正确、日志不全等），不判断实验设计是否合理、基线选择是否恰当、方法是否严谨。
- **不适用于多研究者协作**：任务索引和合并约定假设单个人类操作者，多人并行驱动角色 1 可能导致索引冲突和重复工作。
- **验证器不是代理安全屏障**：普通脚本，如果代理被明确指示绕过规则，可以重写验证器自己；框架针对非对抗性、偶然漂移。
- **安全限制**：框架不提供安全沙箱，代理的 shell 命令可操作宿主机；文档提示用户限制允许列表。
- **可扩展性**：虽然 12 个并行代理可行，但未测试更大规模（如上百个任务同时运行）。
- **实验范围**：仅三个领域，且都由作者运行，缺乏第三方独立复现框架的对比研究。
