## 摘要
大语言模型极大地推动了文本到SQL系统的发展，但将其应用于企业级数据库仍然具有挑战性。现实世界的数据库通常包含庞大且异构的模式、不完整的元数据、特定方言的SQL语法以及难以通过单个SQL查询解决的复杂分析问题。为应对这些挑战，我们提出了ProSPy，一个面向企业级文本到SQL的探查驱动型SQL-Python智能体框架。ProSPy将推理过程组织为四个阶段：首先通过自动探查提取细粒度的数据证据，逐步将大型模式精简为任务相关的上下文，通过一个方言无关的SQL接口获取中间视图，最后使用Python执行灵活的下游分析。该设计结合了SQL在大型数据库上的效率与基于Python的分析的灵活性，同时减少了对不可靠元数据的依赖，并提升了跨SQL方言的鲁棒性。在Spider 2.0-Lite和Spider 2.0-Snow上的实验表明，ProSPy在使用开源和闭源模型时均持续优于强基线方法，在Claude-4.5-Opus上无需多数投票即达到了60.15%和60.51%的执行准确率。进一步分析表明，ProSPy对SQL方言变化具有鲁棒性，并在模式召回率和精确率之间实现了良好的权衡。

## Abstract
Large language models have substantially advanced Text-to-SQL systems, yet applying them to enterprise-scale databases remains challenging. Real-world databases often contain large and heterogeneous schemas, incomplete metadata, dialect-specific SQL syntax, and complex analytical questions that are difficult to solve with a single SQL query. To address these challenges, we propose ProSPy, a Profiling-driven SQL--Python agentic framework for enterprise-scale Text-to-SQL. ProSPy structures the reasoning process into four stages: it first extracts fine-grained data evidence through automatic profiling, progressively prunes large schemas into task-relevant contexts, fetches intermediate views through a dialect-agnostic SQL interface, and finally performs flexible downstream analysis with Python. This design combines the efficiency of SQL over large databases with the flexibility of Python-based analysis, while reducing reliance on unreliable metadata and improving robustness across SQL dialects. Experiments on Spider 2.0-Lite and Spider 2.0-Snow show that ProSPy consistently outperforms strong baselines with both open-source and proprietary models, achieving execution accuracies of 60.15% and 60.51% with Claude-4.5-Opus, without majority voting. Further analysis shows that ProSPy is robust to SQL dialect variations and achieves a favorable trade-off between schema recall and precision.

### 论文核心总结：ProSPy：面向企业级文本到SQL的探查驱动型SQL-Python智能体框架

#### 1. 核心问题与整体含义

- **研究动机**：大型语言模型（LLM）在标准Text-to-SQL基准测试上表现出色，但难以应用于真实的企业级数据库。企业数据库面临三大核心挑战：
    1.  **模式复杂**：数据模式（Schema）庞大且异构，包含大量表格、模糊的命名和嵌套字段。
    2.  **元数据不可靠**：数据库元数据往往不完整或不准确，使得模型难以理解语义。
    3.  **分析任务复杂**：真实业务问题常需要多步逻辑、复杂统计和中间视图，用单一SQL查询难以表达，且不同数据库的SQL方言各异。

- **整体含义**：ProSPy旨在通过一个**探查驱动的SQL-Python智能体框架**，系统性地解决上述挑战。其核心思想是利用**SQL进行高效、大规模数据检索**，利用**Python进行灵活、复杂的下游分析**，将两者优势结合，从而提升LLM在企业级Text-to-SQL任务上的鲁棒性和准确性，减少对不可靠元数据的依赖。

#### 2. 方法论

- **核心思想**：将复杂的数据推理过程分解为四个阶段：**数据探查（Data Profiling）-> 渐进式模式剪枝（Progressive Schema Pruning）-> 智能体数据获取（Agentic Data Fetching）-> Python分析（Python Analysis）**。SQL负责前端的检索和聚合，Python负责后端的复杂计算。

- **关键技术细节与流程**：
    1.  **数据探查（Data Profiling）**：
        - 自动对原始数据库表进行静态分析，取代了传统方法中耗时的“LLM-数据库”交互探索。
        - 为每个列提取结构化证据，包括：语义类型（指标、维度、标识符、时间等）、统计信息（分布、空值率）、样本值和嵌套字段结构。
        - 结果被序列化为结构化JSON，注入到模型上下文中。此过程只需运行一次，结果可对所有相关问题复用，提高效率。

    2.  **渐进式模式剪枝（Progressive Schema Pruning）**：
        - 目标是从庞大的原始模式（E）中构建一个**既紧凑又任务相关**的模式子集（E'），平衡召回率和精确率。
        - **表格级剪枝**：将模式分批，由LLM基于问题（Q）和当前保留的模式（E<sup>(t)</sup>）逐步识别并排除不相关的表格。
        - **列级剪枝**：在保留的表格中，由LLM进一步排除不相关的列。
        - 最终生成精简的、任务相关的模式上下文，降低下游推理的复杂性。

    3.  **智能体数据获取（Agentic Data Fetching）**：
        - 不再依赖单个复杂SQL，而是通过迭代方式构建多个中间视图（Views）。
        - **规划与执行**：智能体首先根据精简后的模式和问题规划所需数据，然后每次生成一个或多个视图定义。
        - **方言无关的领域特定语言**：视图定义使用一种轻量的DSL（域特定语言）表达，该DSL围绕“维度”、“指标”和“条件”三大核心组件组织，由智能体生成。
        - **动态编译执行**：DSL表示的视图定义随后被**编译（Transpile）** 成目标数据库（如Snowflake, BigQuery）可执行的SQL方言，从而屏蔽了SQL方言差异，提升了鲁棒性。

    4.  **Python分析（Python Analysis）**：
        - 所有已生成的中间视图数据以CSV文件形式导出，提供给配备Python工具的智能体。
        - 智能体通过Python（如pandas）加载CSV数据，执行SQL难以胜任的多步、灵活的复杂分析，最终生成答案CSV文件。
        - 智能体可以观察执行结果，进行错误修正和迭代。
