## 摘要
大型语言模型可以将研究者的意图转化为可运行的matplotlib代码，但生成的图表很少能不经多轮手动修改就直接用于论文。我们认为，开放性问题不在于图表代码生成，而在于图表发表：使输出看起来像顶级会议的图表，适应目标布局，并响应精确的作者编辑。我们提出chart-plot，一个通过三个组件弥合这最后一英里的代理框架：(1) 一个风格感知的代码生成器，其条件是基于从目标会议已接受图表中提取的文本风格技能；(2) 一个部署感知的渲染循环，在目标LaTeX上下文中编译图表并不断修改直到满足布局约束；(3) 一个结构化编辑层，将每个图表元素暴露为可直接操作的控制柄。我们报告了三种图表类型案例研究（分组条形图、缩放线图、配对分布）的初步结果和一项小型用户研究。

## Abstract
Large language models can translate a researcher's intent into runnable matplotlib code, yet the resulting chart rarely lands in a paper without multiple rounds of manual revision. We argue that the open problem is not chart code generation but chart publication: making the output look like a top-venue figure, survive the target layout, and respond to precise author edits. We present chart-plot, an agentic harness that closes this last mile through three components: (1) a style-aware code generator conditioned on a textual style skill distilled from accepted figures at the target venue, (2) a deployment-aware render loop that compiles the chart inside the target LaTeX context and revises until layout constraints are met, and (3) a structured edit layer that exposes every chart element as a directly manipulable handle. We report early results on three chart-type case studies (grouped bar, scaling line, paired distributions) and a small user study.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：大语言模型（LLM）能够将研究者的意图和CSV数据快速转化为可运行的matplotlib图表代码，但生成的图表极少能直接用于论文发表，通常需要经历2-3轮手动修改。
- **核心矛盾**：作者认为，当前开放问题不是“图表代码生成”（已有LIDA、ChartLlama、VisPath等系统），而是“图表发表”——即让生成图表具备顶级会议论文的视觉风格、能够适应目标论文的布局约束（如列宽、字体大小）、并支持作者对细节的精确调整。
- **三大失败模式**：
  - **风格不匹配**：AI会议偏好低饱和度调色板、无衬线字体；系统类会议偏好衬线字体、阴影条形图、显式误差棒。默认LLM输出视觉上“不对”。
  - **部署不匹配**：matplotlib默认尺寸（6.4×4.8英寸）在双栏ACM模板（栏宽3.3英寸）下，刻度标签不可读、图例遮挡数据。
  - **编辑不匹配**：图表接近正确时，作者想做微小几何调整（移动图例、缩小注释），重新提示LLM不可靠，因为模型无法仅从文本指令定位像素级变化。
- **整体含义**：作者提出**chart-plot**——一个代理框架（harness），在LLM周围构建确定性脚手架，注入模型无法从提示中推断的发表上下文（目标模板列宽、会议视觉惯例），将图表生成到发表的“最后一英里”自动化。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：使用“harness”理念，将LLM的原始生成能力引导为发表就绪的产物，通过三个层次覆盖从全自动化到作者控制的频谱。

  - **① 风格感知代码生成器**
    - 构建语料库：从目标会议已接受论文中提取图表（PNG+标题），人工策选并标记会议类型和图表类型。
    - 蒸馏为**文本风格技能**：一个Markdown格式的摘要文件，记录重复出现的视觉惯例（调色板、字体大小、图例位置、误差棒样式）。技能文件是独立、版本可控的指令文件，可在生成时注入LLM的上下文提示中。
    - 作者可为不同会议或实验室自定义新技能文件，无需重新训练。

  - **② 部署感知渲染循环**
    - 将生成的图表代码在目标LaTeX模板中编译（而非孤立渲染），直接检测布局级错误：列溢出、字体不可读、长宽比漂移。
    - 工作流程：编译 → 测量渲染图表边界框 → 生成结构化诊断（编译失败、宽度/字体问题、长宽比漂移、标题溢出） → 转换为具体代码编辑指令（如“将刻度标签字体增大到至少6pt”） → 反馈给LLM进行下一轮代码生成 → 循环直到收敛、达到迭代上限或模型失败。
    - 示例：8×6英寸图表在3.35英寸单栏中触发宽度和字体违规，一次修订后缩小到3.35×2.34英寸，所有检查通过。

  - **③ 结构化编辑层（多模态编辑层）**
    - 针对重新提示LLM的两个局限：自由文本指令（“把图例往右移一点”）难以收敛，且LLM看不到渲染结果，每次编辑是视觉结果的猜测。
    - 解决方法：在sandbox中执行生成代码，遍历matplotlib Figure对象树，为每个元素（轴标签、图例、线、补丁）分配稳定标识符和边界框。
    - Web界面：在渲染图上覆盖可点击目标，选中元素打开上下文检查器，控件取决于元素种类（图例：位置、列数、字体大小、框架切换；线条：颜色、宽度、样式、标记；文本：内容、大小、颜色）。每个控件映射到具体matplotlib代码突变，修改可重现且与自动化部署修复兼容。

- **共享表示**：经过代码生成器执行后，系统生成一个布局表示（Layout Representation），包含所有元素的稳定标识符和边界框，共享给部署循环和编辑层。

## 3. 实验设计

## 6. 主要结论与发现

- **默认LLM输出是“可行但不可发表”**：三个案例中基线图表代码可运行，但视觉风格偏离会议惯例，且栏宽下可读性差。
- **chart-plot在一次生成中同时解决风格和部署问题**：通过风格技能注入和部署循环，三个案例的输出均达到发表质量（符合VLDB风格、栏宽可读）。
- **约束违规可诊断**：部署循环产生具名诊断（字体大小、宽度、长宽比的具体测量值），而非自由文本视觉模型批评，便于下一轮修复。
- **几何编辑零LLM代币成本**：通过结构化编辑层的代码突变，每次编辑花费很少，而重新提示LLM约需3000代币。
- **用户研究**：chart-plot在所有五个问题上平均Likert评分提高1.50-2.50分，最大差距在栏宽可读性（4.5 vs 2.00）和持续使用意愿（4.5 vs 2.50），最小在美学吸引力（4.25 vs 2.75）。编辑维度得分4.5 vs 2.75。

## 7. 优点

- **问题定义精准**：首次系统提出“图表发表”而非“图表代码生成”才是瓶颈，并归纳三类具体失败模式。
- **系统设计优雅**：三层结构对应自动化谱系（推荐→自动→可控），共享布局表示确保各层协同。
- **风格技能机制实用**：文本Markdown文件而非模型重训练，可扩展、可版本控制、可手工调整，适合社区共建。

- **编辑层直观高效**：直接操纵+代码突变，避免了LLM反复提示的开销和不确定性。
