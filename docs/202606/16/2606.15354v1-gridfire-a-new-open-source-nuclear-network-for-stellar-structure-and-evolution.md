## 摘要
我们提出了一种新颖的核网络实现GridFire，其开发重点在于效率、易用性以及自动物理扩展。在这首篇论文中，我们详细概述了GridFire的数值方法、性能特征，并与现有的核网络实现pynucastro和MESA的net模块进行了比较。我们发现，总体而言，GridFire的性能与这些当前一代核网络代码相似，但所需的用户输入和设置显著减少。此外，GridFire采用了灵活的基于“视图”的物理引擎，允许研究人员实现领域特定的物理内容，而无需修改底层源代码。GridFire已根据开源许可证GPL v3.0发布，并最终将整合到即将推出的4D-STAR恒星结构演化代码中。

## Abstract
We present a novel nuclear network implementation, GridFire, which has been developed with a focus on efficiency, ease of use, and automatic physical extension. In this first paper we provide a detailed overview of GridFire's numerics, performance characteristics, and a comparison to pre-existing nuclear network implementations pynucastro and MESA's net module. We find that generally GridFire performs similarly to and requires significantly less user input and setup than these current generation nuclear network codes. Further, GridFire has been developed with a flexible "view" based physics engine that allowing researchers to implement domain specific physics without modifying the underlying source code. GridFire has been released under an open-source license, GPL v3.0, and will eventually be incorporated into the forthcoming 4D-STAR stellar structure evolution code.

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- 采用**策略模式**（strategy pattern）和**装饰器模式**（decorator pattern）将物理学（Engine）与数值求解器（Solver）严格分离。
- 物理计算由“引擎栈”完成：最底层是 `GraphEngine`（存储网络拓扑、计算反应率、Jacobian），上层可叠加多个 `EngineView`（如准静态平衡检测、用户自定义物理）。
- 求解器将引擎视为黑盒，调用其接口获取右端项和 Jacobian，再通过隐式积分器（CVODE BDF）推进时间。

### 关键技术细节

**1. 反应率处理**
- 强反应率来自 JINA REACLIB 数据库（Z ≤ 26），采用七参数解析公式（Eq.3）。
- 弱反应率默认使用 REACLIB 表格（含启发式中微子损失近似），支持实验性的 Weak Rate Library（WRL）。
- 逆反应率基于详细平衡原理计算（实验性），使用 Rauscher-Thielmann 配分函数。
- 等离子体屏蔽采用 Salpeter 弱屏蔽模型。

**2. 自动微分**
- 使用 CppAD 库进行自动微分，精确计算 Jacobian 矩阵，避免手写导数错误。
- 对网络拓扑“录带”（taping），仅在拓扑变化时重新录带，提升效率。

**3. 引擎视图与准静态平衡（QSE）**
- `MultiscalePartitioningEngineView` 自动检测处于准静态平衡的物种组，将其时间导数设为零，通过 KINSOL 非线性求解器代数求解丰度。
- 实现 8 步分区算法：网络启动 → 时标分区 → 连通性分析 → 种子识别 → 通量验证 → 剪枝 → 二次验证 → 合并。

**4. 求解器**
- `PointSolver`：单区、热力学静态的积分方案，使用 CVODE BDF 隐式求解器 + 稠密线性求解器。
- `GridSolver`：多区并行求解器，利用多线程（OpenMP）加速，实现约 70% 每核效率提升。
- 触发器系统（收敛失败、时间步骤降、非对角线项、边界通量）自动触发网络重投影，保证积分稳定。

**5. 网络拓扑自动构建**
- 用户仅需提供一个种子组成和网络构建深度，GridFire 从种子出发执行广度优先搜索，自动收集反应和物种，形成有向超图。

## 6. 主要结论与发现

1. **性能相当**：GridFire 在丰度演化和能量产生上与 pynucastro、MESA net 吻合良好，差异主要由率表差异引起（如 ¹²C 丰度差 0.3 dex 源于 ¹⁴N(p,γ)¹⁵O 率表不同）。
2. **用户输入大幅减少**：用户仅需提供种子组成和构建深度，无需定义反应路径或物种列表。
3. **准静态平衡自动检测有效**：QSE 近似引入的误差极小（主丰度 < 1e-3 dex，能量 < 0.004 dex），可有效加速计算。
4. **重投影平滑**：使用 BoundaryFluxTrigger 后，重投影对累积能量引入的相对误差仅约 1e-4。
5. **BBN 验证**：简单 BBN 模型再现了主要结果（D/H 与 Cooke+2018 一致在 13% 内）。
6. **多区并行有效**：GridSolver 相比 PointSolver 可实现约 10 倍加速（16 核）。
7. **可扩展性良好**：通过视图架构，用户可轻松添加新物理（如新屏蔽模型、热力学耦合等）而不修改核心代码。

## 7. 优点

- **自动化程度高**：自动构建拓扑、自动检测 QSE、自动剪枝、自动触发重投影。
- **架构灵活**：引擎-视图-求解器三层分离，支持 Python 扩展（通过 pybind11），也支持 C/Fortran/JavaScript 接口。
- **数值鲁棒**：使用 CVODE BDF + 自动微分精确计算 Jacobian，保证稳定性；触发器系统防止非物理状态。
- **性能优化**：大规模预计算缓存（加速 50 倍）、稀疏 Jacobian 着色、多线程并行。
- **开源友好**：GPL v3.0 许可证，提供预编译 Python wheel，降低使用门槛。
- **领域适用性**：针对主序星量身定制，同时支持 BBN、未来可扩展至更高能阶段。

## 8. 不足与局限

- **热力学解耦**：目前采用操作分裂方式，热力学状态固定，未实现全耦合；未来版本才计划加入。
- **反应率范围受限**：默认仅包含 Z ≤ 26 的强反应（不包含光致蜕变），且弱反应默认使用 REACLIB 表格（中微子损失低估约 0.4%）。
- **逆反应率实验性**：详细平衡计算目前实验性，未在本文中使用；配分函数导入导数需有限差分，增加开销。
- **QSE 误差**：在痕量物种（如 Li 丰度 ≤ 1e-14 mol/g）上相对误差可达 1 dex；能量误差虽小，但在热力学耦合模型中可能积累为系统性偏差。
- **对比覆盖有限**：与 MESA net 仅对比一个网络文件，未覆盖不同网络规模或不同热力学条件；与 pynucastro 的对比虽多，但两者率表来源可能不完全一致。
- **内存占用**：对于大型网络（>500 物种），引擎内存约为百 MB，虽比 MESA 整体小（BBQ+MESA 约 1.5 GB），但在内存受限环境仍可能成为瓶颈。
- **未测试极端条件**：硅燃烧、核心塌陷、超新星等高温高密环境尚未验证；当前代码未包含这些区域所需的完整物理（如光致蜕变、强屏蔽）。
- **性能比较需谨慎**：MESA net 因设计更保守（常重新计算 Jacobian）而慢于 GridFire，但 MESA 在耦合求解下可能更具优势；pynucastro 通过 JIT 编译更快，但需要预定义网络。
